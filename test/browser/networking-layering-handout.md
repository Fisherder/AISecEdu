## 1. 为什么要分层（对应教材第 1 章 P12–P20）

网络通信要同时解决很多互不相关的问题：信号怎么传、相邻设备怎么确认收到、跨网络怎么找到对方、
两端进程怎么区分、应用数据怎么表示。把这些问题按职责切成若干层，每层只依赖下一层提供的服务，
就得到"分层"。分层带来两个直接好处：

1. **独立演进**：只要接口不变，某一层换实现不影响其他层（例如以太网换成 Wi-Fi，IP 层不变）。
2. **职责清晰**：排障时可以按层定位，先看物理链路，再看网络可达，最后看应用。

## 2. TCP/IP 四层模型

| 层次 | 中文名 | 主要职责 | 典型协议 | 数据单元 |
| --- | --- | --- | --- | --- |
| 应用层 | Application | 面向具体业务，定义报文格式与交互语义 | HTTP、DNS、SMTP、SSH | 报文 Message |
| 传输层 | Transport | 端到端进程间通信、复用分用、可靠性或时延控制 | TCP、UDP | 报文段 Segment / 数据报 Datagram |
| 网络层 | Internet | 编址与路由，把分组从源主机送到目的主机 | IP、ICMP、ARP（常归此层讲解） | 分组 Packet |
| 网络接口层 | Network Interface | 在直连链路上成帧与传输，介质访问控制 | Ethernet、Wi-Fi、PPP | 帧 Frame |

### 2.1 每层的一句话记忆

- 应用层：**说什么**。
- 传输层：**哪个进程在说，要不要保证说到**。
- 网络层：**怎么从这台主机走到那台主机**。
- 网络接口层：**这一跳的线路上怎么把比特送出去**。

### 2.2 封装与解封装

发送方自上而下逐层加头：应用数据被传输层加上 TCP 头形成报文段，再被网络层加上 IP 头形成分组，
再被网络接口层加上帧头帧尾形成帧。接收方自下而上逐层去头，交给对应层的处理程序。
每一层的头部只被对端的同一层解释，这就是"对等层通信"。

## 3. 常见误区

1. **"TCP/IP 就是 TCP 加 IP"**。TCP/IP 是一整套协议族，还包含 UDP、ICMP、DNS、HTTP 等。
2. **"ARP 属于网络接口层"**。ARP 直接封装在以太网帧上，很多教材把它归到网络层或链路层之间；
   本课程统一按"网络层讲解、链路层封装"处理，考试时以课堂说明为准。
3. **"分层越多越好"**。分层有封装开销和跨层信息丢失的代价；OSI 七层是教学参考模型，
   工程实现是 TCP/IP 四层。
4. **"UDP 不可靠所以没用"**。UDP 没有重传和拥塞控制，时延更可预测，适合实时音视频、
   DNS 查询和需要自行实现可靠性的场景。

## 4. 课堂练习（含答案与解析）

**练习 1**：浏览器访问 `https://example.edu` 时，DNS 查询、TCP 三次握手、HTTP 请求
分别发生在哪一层？

- 参考答案：DNS 与 HTTP 在应用层；TCP 三次握手在传输层；承载它们的 IP 分组在网络层，
  以太网帧在网络接口层。
- 解析：DNS 与 HTTP 都是应用程序协议；三次握手是 TCP 建立连接的过程，属于传输层功能；
  所有上层数据最终都由 IP 与链路层承载。

**练习 2**：某台主机能 ping 通网关，但打不开网页。按分层模型应该先查哪几层？

- 参考答案：先确认应用层（浏览器代理、URL、端口）与传输层（TCP 443 是否被拦截），
  再查 DNS 解析；网络层到网关已通，说明路由与链路基本正常。
- 解析：ping 通网关只证明网络接口层与网络层可达，不代表传输层端口可达或应用层配置正确。
