🔍 攻击概述

这是一次典型的TLS降级攻击（Downgrade Attack）。攻击者作为中间人（MITM），拦截了客户端与服务器之间的TLS握手流量，并篡改了ClientHello中的版本信息，迫使双方使用过时且不安全的TLS 1.0协议进行通信。

🎯 攻击链

  • 阶段1 — 拦截：客户端发送支持TLS 1.3的ClientHello（数据包#3），MITM截获该包。
  • 阶段2 — 篡改：MITM移除ClientHello中的supported_versions扩展（或将其改为仅支持TLS 1.0），然后将修改后的请求转发给服务器。
  • 阶段3 — 降级响应：服务器看到仅支持TLS 1.0的请求，返回TLS 1.0的ServerHello（数据包#4），使用弱加密套件TLS_RSA_WITH_AES_128_CBC_SHA。
  • 阶段4 — 弱加密通信：后续通信使用RSA密钥交换和AES-128-CBC，攻击者可利用已知弱点进行解密或中间人攻击。

🚩 关键异常数据包

数据包#4 (ServerHello) 是最关键的异常：客户端明确支持TLS 1.3（supported_versions=0x0304），但服务器返回的却是TLS 1.0 (0x0301)。这表明中间有人篡改了握手参数。

数据包#7 (ClientKeyExchange) 也值得注意：使用了RSA密钥交换而非TLS 1.3的ECDHE，不支持前向安全性。

🛡️ 防御措施

  • 启用TLS 1.3-only模式：在服务器和客户端配置中禁用TLS 1.0/1.1，仅允许TLS 1.2+。
  • 证书固定（Certificate Pinning）：防止MITM使用伪造证书。
  • 严格传输安全（HSTS）：强制浏览器使用HTTPS并阻止降级。
  • 监控告警：对TLS版本不匹配、弱加密套件的使用设置SIEM告警规则。
  • 加密套件白名单：仅允许AEAD加密套件（如AES-GCM、ChaCha20-Poly1305），禁用CBC模式。
