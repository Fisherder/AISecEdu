🧠 零知识证明（ZKP）核心属性

完备性：如果Peggy真的知道秘密，她总能通过验证（100%成功）。

可靠性：如果Peggy在说谎，每轮她只有50%概率蒙对。n轮后蒙混过关的概率为：

P(作弊成功) = (1/2)ⁿ

10轮后 ≈ 0.098%，20轮后 ≈ 0.000095%。

零知识性：Victor（你）始终不知道秘密是什么——你只看到Peggy从你指定的路径出来，但不知道她是否使用了魔法门。

⚔️ 攻击视角：尝试作弊的Prover

如果Peggy不知道秘密，她只能走一条路并希望Victor恰好挑战那条路。每轮50%概率。Victor需要随机且不可预测地选择挑战路径。如果Victor总是选"左边"，作弊者就可以每次都走左边——这就是为什么验证者的随机性至关重要。

// 攻击者策略：固定走一条路 → 50%成功率/轮 → n轮后 (½)ⁿ 总成功率

🛡️ 防御视角：协议设计保障

防御措施即协议本身：验证者必须使用真随机挑战。在现实世界的ZKP中（如Schnorr协议、zk-SNARKs），挑战由随机预言机（Random Oracle）或Fiat-Shamir变换生成，确保证明者无法预测。

// 防御：验证者随机挑战 + 多轮迭代 → 将作弊概率压至可忽略

🌐 现实世界应用

ZKP用于：区块链隐私（Zcash的zk-SNARKs）、身份验证（不泄露密码）、安全多方计算、电子投票、可验证计算等。
