💡 提示：正常登录需要正确的用户名和密码。但漏洞在于查询语句是拼接而成的……

🔴 漏洞代码（存在 SQL 注入）

VULNERABLE — 字符串拼接 
// 危险！直接将用户输入拼接到 SQL 查询中
                    function vulnerableLogin(username, password) {
                    const sql = `SELECT * FROM users
                    WHERE username='${username}'
                    AND password='${password}'`;
                    // 执行查询...
                    }

🟢 修复代码（参数化查询 / Prepared Statement）

FIXED — 参数化查询 
// 安全：使用参数化查询，用户输入不会被解释为 SQL 代码
                        function safeLogin(username, password) {
                        const sql = `SELECT * FROM users
                        WHERE username = ? AND password = ?`;
                        const params = [username, password];
                        // db.query(sql, params) — 参数与查询分离
                        }
🔍 原理说明： 在漏洞版本中，用户输入被直接拼接到 SQL 字符串中。当输入 ' OR 1=1 -- 时，单引号闭合了原查询的字符串边界，OR 1=1 添加了一个恒真条件，-- 注释掉了后续的密码检查部分，导致查询返回所有用户，从而绕过登录。修复方案使用 参数化查询（Prepared Statement），将 SQL 结构与用户数据分离，数据库引擎不会将参数解释为 SQL 代码，从根本上杜绝了注入。
