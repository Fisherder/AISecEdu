🔬 格式化字符串漏洞完整分析

根因：printf(input_buf) 将用户可控的数据作为格式字符串的第一个参数。当用户输入包含格式说明符（如 %x、%n）时，printf() 会从栈上读取额外参数或向内存写入数据，导致信息泄露（CWE-200）和任意内存写入。

攻击链：

  1. 信息泄露：使用 %x %x %x... 遍历栈槽位，读取局部变量（secret_key=0x1337, access_level=0x00）和栈金丝雀等敏感数据。
  2. 内存写入：使用 %n 将已打印字符数写入栈上任意地址。结合直接位置参数 %N$n 可精准覆盖目标变量（如将 access_level 改为 0x1337 实现特权提升）。
  3. 任意地址写入：在输入中嵌入目标地址字节，利用 %N$n 写入任意值到任意内存位置，可劫持 GOT 表、返回地址等。

修复方案：

  • 方案 A（推荐）：printf("%s", input_buf); — 显式指定格式字符串，用户输入仅作为字符串参数。
  • 方案 B：puts(input_buf); — puts 不接受格式说明符，天然安全（但会追加换行）。
  • 方案 C：fputs(input_buf, stdout); — 同样安全，无自动换行。
