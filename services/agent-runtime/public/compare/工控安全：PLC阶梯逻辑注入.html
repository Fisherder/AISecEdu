步骤 5/6

正常逻辑 vs 恶意逻辑对比

✅ 正常阶梯逻辑（安全）

E-Stop常闭触点直接串联在电机回路中。按下E-Stop → 电路断开 → 电机停止。

🔴 恶意注入逻辑（危险）

← 恶意旁路

注入的并联路径（M9.9远程触点）绕过E-Stop。即使E-Stop断开，电流仍可通过旁路供给电机。

🔍 攻击原理分析： 攻击者利用对PLC的编程访问权限，在E-Stop常闭触点两端并联了一个由远程信号控制的常开触点（M9.9）。 这创建了一条"影子路径"——当攻击者远程闭合M9.9时，电流可以完全绕过物理E-Stop按钮。 从操作员视角，急停按钮被按下但设备仍在运转，造成严重的安全幻觉。
步骤 6/6 防御学习

PLC代码签名与变更检测防御

如何防御此类阶梯逻辑注入攻击？以下是两种关键防御措施。请在下方编写变更检测的核心逻辑来完成防御学习。

🔐 PLC代码签名

每次向PLC下载程序时，工程软件（如TIA Portal）使用数字签名对阶梯逻辑程序进行哈希计算并加密。 PLC在上电或运行时验证签名——如果程序被非法修改，签名验证失败，PLC将拒绝执行并发出报警。 这类似于操作系统的Secure Boot机制。

📋 变更检测与审计

通过定期比对PLC中运行的程序与"黄金镜像"（已知安全的基准版本）， 检测任何未经授权的程序段修改。结合版本控制和审计日志， 记录谁在何时对PLC程序进行了何种变更。

攻击链（Kill Chain）

  1. 初始访问： 攻击者通过网络或物理方式获得PLC编程访问权限（如TIA Portal工程站）。
  2. 执行： 攻击者修改阶梯逻辑程序，在E-Stop触点两端并联远程控制的常开触点。
  3. 持久化： 恶意程序段被写入PLC非易失性存储，断电重启后依然存在。
  4. 影响： 操作员按下E-Stop但传送带继续运转——安全联锁被破坏，可能导致人员伤亡。

防御措施总结

  • 🔐 PLC代码签名： 使用数字签名确保程序完整性，非法修改导致签名失效。
  • 📋 变更检测： 定期比对运行程序与黄金镜像，检测未授权修改。
  • 🔒 访问控制： 限制PLC编程端口物理访问，使用强密码和RBAC。
  • 📡 网络分段： 将OT网络与IT网络隔离，部署工业防火墙。
  • 📊 审计日志： 记录所有PLC程序变更操作，便于事后追溯。

真实世界参考

此类攻击与震网（Stuxnet）病毒的攻击手法有相似之处——通过修改PLC程序来改变物理设备行为，同时向监控系统反馈伪造的正常状态值。在工控安全领域，CWE-74（通用注入）和CWE-94（代码注入）覆盖了此类漏洞类型。Siemens S7-1200系列PLC支持专有技术保护（Know-How Protection）和访问级别密码作为基本防护。
