Modbus Protocol Security Weaknesses

The Modbus protocol, originally designed for serial communication in isolated industrial environments, lacks fundamental security features:

  • No Authentication: Any device on the network can send commands; the slave cannot verify the master's identity.
  • No Encryption: All data travels in plaintext, allowing easy sniffing and manipulation.
  • No Integrity Checks (beyond CRC): CRC-16 catches transmission errors but offers no protection against malicious tampering.
  • Function Code Abuse: Attackers can scan function codes, write to critical registers, or perform DoS by flooding.

Attack Vectors Demonstrated

  • Unauthorized Write (FC06/FC16): Overriding pump speed to 100% while closing the drain valve causes tank overflow.
  • Pump Shutdown DoS (FC05): Writing 0 to the pump coil stops the pump, potentially draining the tank and causing cavitation damage.
  • False Data Injection: Writing to holding registers that feed the HMI can make operators see false readings while the physical process behaves differently.

Defense Strategy

  • Modbus Firewall with Allowlist: Only permit explicitly authorized function codes and register ranges. Block all writes (FC05, FC06, FC16) unless from known engineering stations.
  • Network Segmentation: Place ICS networks behind firewalls, separate from corporate IT networks (Purdue Model).
  • Protocol Monitoring: Detect anomalies like rapid successive writes, out-of-range values, or function code scanning.
  • Secure Gateways: Use Modbus-to-secure-protocol gateways that add authentication and encryption at the boundary.
