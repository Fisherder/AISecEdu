📄 完整攻击分析报告

🔍 攻击根因

802.11管理帧（包括Beacon、Probe Response、Deauthentication）在设计上缺乏认证机制。任何设备都可以伪造AP的MAC地址发送Deauth帧，因为接收方无法验证该帧是否真的来自声称的发送方。这使得Evil Twin + Deauth攻击成为可能。

⛓️ 攻击链 (Kill Chain)
  1. 侦察：扫描目标区域WiFi，获取合法AP的SSID、BSSID、信道、信号强度及已连接客户端MAC。
  2. 部署伪造AP：在相同或邻近信道启动与合法AP相同SSID的Evil Twin AP（不同BSSID）。
  3. Deauth攻击：向客户端发送伪造的Deauthentication帧（源MAC伪造成合法AP），迫使客户端断开。
  4. 客户端漫游：客户端自动扫描并连接到信号更强（或唯一可用）的同名SSID — 即Evil Twin。
  5. 凭证捕获：Evil Twin提供Captive Portal或中间人拦截，捕获用户输入的WiFi密码或其他凭证。
🛡️ 防御方案：802.1X EAP-TLS

EAP-TLS (Extensible Authentication Protocol - Transport Layer Security) 提供双向证书认证：
• AP必须向客户端出示有效的服务器证书（由受信任CA签发）
• 客户端必须向AP出示有效的客户端证书
• 双方通过TLS握手建立加密隧道交换认证信息
• 攻击者即使伪造SSID也无法提供合法证书，客户端不会连接
• 需要部署RADIUS服务器（如FreeRADIUS）进行证书验证
• 结合WPA3-Enterprise可提供更强的保护
