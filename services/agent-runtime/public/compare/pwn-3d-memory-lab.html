🔴 漏洞根因

strcpy() 不检查目标缓冲区大小。当 user_input 长度超过16字节时，数据会连续写入栈上更高地址，依次覆盖保存的EBP和返回地址(RET)。

🟠 利用链

  1. 构造超长输入（>16字节）
  2. strcpy 逐字节复制，越过buffer边界
  3. 覆盖EBP（栈帧指针）
  4. 覆盖RET（返回地址）→ 函数返回时跳转到攻击者控制地址

🟢 防御措施

  • 使用 strncpy(buf, src, sizeof(buf)) 限制复制长度
  • 启用栈保护 (-fstack-protector)，插入canary金丝雀值
  • 启用ASLR（地址空间布局随机化）
  • 启用NX/DEP（栈不可执行）
  • 使用更安全的语言（Rust, Go等）

📚 现实参考

CWE-121: Stack-based Buffer Overflow
CVE-2019-0708 (BlueKeep) 等大量CVE均涉及缓冲区溢出。现代编译器默认启用栈保护可检测此类攻击。
