🔍 攻击概览

这是一次典型的工控HMI界面欺骗攻击，手法与Stuxnet震网病毒高度相似。攻击者通过中间人（MITM）方式插入到PLC与HMI之间的Modbus TCP通信链路中，截获并篡改关键寄存器读数。

🎯 攻击链分析

  1. 初始接入：攻击者获得网络访问权限，在PLC（192.168.1.1）和HMI（192.168.1.10）之间建立MITM位置（192.168.1.99）。
  2. 流量截获：HMI定期通过功能码0x03（读保持寄存器）轮询离心机状态寄存器（地址0x0064起）。
  3. 响应篡改：PLC实际返回转速1487 RPM、温度87°C、振动9.2 mm/s——均超出安全阈值。攻击者拦截该响应，替换为伪造数据（1064 RPM、42°C、0.8 mm/s）后转发给HMI。
  4. 恶意写入：攻击者通过功能码0x06向VFD寄存器（地址0x00C8）写入超速设定值1450，持续推高离心机转速。
  5. 持久隐藏：操作员看到的始终是"正常"数据，无法察觉离心机正在被推向物理极限。

🛡️ 防御建议

  • 网络分段：将ICS/SCADA网络与企业网络严格隔离，实施VLAN和防火墙规则。
  • 协议认证：部署Modbus Secure或OPC UA等支持加密和认证的协议替代裸Modbus TCP。
  • 异常检测：部署ICS-aware IDS（如Snort with Modbus规则），监控响应时间异常和寄存器值突变。
  • 冗余校验：在关键传感器上部署独立于PLC的物理读数通道，与HMI显示值进行交叉验证。
  • 深度包检测：在HMI与PLC之间部署DPI设备，检测并告警来自非预期源IP的Modbus响应。

📚 真实世界参考

Stuxnet（2010年）攻击伊朗核设施时使用了完全相同的手法——拦截WinCC/HMI与S7-300 PLC之间的通信，将离心机转速的监控数据替换为正常值，同时向变频器发送超速指令，导致约1000台离心机因超速旋转而损毁。
