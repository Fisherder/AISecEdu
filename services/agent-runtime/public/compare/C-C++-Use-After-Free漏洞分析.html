🔴 漏洞根因

第20行 delete admin 释放了 UserAccount 对象占用的堆内存，但未将指针置为 nullptr。第25行通过悬空指针调用 admin->printInfo()，此时该内存区域可能已被第23行的 guest 对象重用，导致读取到错误或攻击者可控的数据。

🟠 利用链

1. 释放 admin 对象（堆块归还给分配器）→ 2. 攻击者触发新分配（guest 对象或精心构造的数据）占据同一内存块 → 3. 悬空指针访问被覆盖的内存 → 4. 类型混淆：将 guest 的数据按 UserAccount 布局解释 → 5. 可能的信息泄露（读取 isAdmin/username）或代码执行（虚表劫持）。

🟢 修复方案

方案A（最小修复）：delete admin; admin = nullptr; —— 后续对 nullptr 的解引用会立即崩溃（可预测的失败），而非静默的数据损坏。

方案B（推荐）：使用 std::unique_ptr<UserAccount> admin = std::make_unique<UserAccount>(...); —— 智能指针在析构时自动释放内存并将内部指针置空，从根本上消除悬空指针。

🔵 现实世界参考

CWE-416 是 OWASP Top 25 中最危险的软件弱点之一。Chrome、Firefox、Linux 内核等大型项目中 UAF 漏洞屡见不鲜。现代防御包括：AddressSanitizer (ASan)、Control Flow Integrity (CFI)、隔离堆 (PartitionAlloc) 以及 Rust 等内存安全语言。
