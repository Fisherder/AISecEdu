步骤 5/5 防御：Zigbee 3.0 密钥轮换

攻击之所以成功，是因为网络使用静态默认链接密钥且从不轮换网络密钥。Zigbee 3.0 引入了 Install Code 和定期密钥轮换来防御此类攻击。

🔴 易受攻击的配置 (Legacy)

  • 使用公开默认链接密钥 "ZigbeeAlliance09"
  • 网络密钥永不轮换
  • 所有设备共享同一密钥
  • 攻击者一旦获取密钥即可永久访问

🟢 Zigbee 3.0 安全配置

  • 每设备唯一 Install Code (出厂预置)
  • 网络密钥定期轮换 (建议24小时)
  • 密钥派生使用 AES-128-CCM
  • 旧密钥过期后攻击者无法注入指令

攻击链分析 (Attack Chain): 1. 侦察: 攻击者使用 Zigbee 嗅探器被动捕获信标帧，发现网状网络拓扑。 2. 凭证获取: 捕获传输密钥包(APS Transport Key)，发现使用默认链接密钥"ZigbeeAlliance09"(Key Type 0x01, 无Install Code)。 3. 密钥推导: 使用公开默认密钥解密传输密钥包，获取当前网络密钥。 4. 指令注入: 使用网络密钥加密恶意ZCL指令(门锁集群0x0101, 解锁命令0x01)，注入网络。 5. 影响: 智能门锁被远程开启，物理安全被绕过。 根因: 遗留Zigbee设备使用众所周知的默认链接密钥("ZigbeeAlliance09")，且网络密钥从不轮换。一旦攻击者在设备入网时捕获传输密钥包，即可解密获取网络密钥，永久访问网络。 CVSS 3.1 向量 (估算): CVSS:3.1/AV:A/AC:L/PR:N/UI:N/S:C/C:H/I:H/A:H — 评分 9.3 (Critical) - 攻击向量(AV): 相邻网络 (Adjacent) - 攻击复杂度(AC): 低 (仅需被动嗅探) - 权限要求(PR): 无 - 范围(S): 改变 (从Zigbee网络到物理安全) Zigbee 3.0 防御措施: - Install Code: 每设备出厂预置唯一128位代码，用于初始密钥协商。 - 密钥轮换: 信任中心(协调器)定期发起网络密钥更新，旧密钥在过渡期后失效。 - 帧计数器: 防止重放攻击。 - 设备认证: 使用AES-128-CCM进行消息完整性校验。 参考来源: - Zigbee Alliance, "Zigbee 3.0 Security Features" - Jansen, "Assessing Smart Home Security: A Zigbee Case Study" (Section 6.1.2, Attack A2) - Securelist, "Zigbee Protocol Security Assessment" - HKCERT, "IoT Device (Zigbee) Security Study"
