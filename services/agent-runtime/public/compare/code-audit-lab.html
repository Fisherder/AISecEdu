OWASP 反序列化防护最佳实践

  • 白名单优先：仅允许反序列化已知安全的类（如业务DTO）。
  • 使用ObjectInputFilter（Java 9+）：通过setObjectInputFilter()或ObjectInputFilter.Config.createFilter()设置过滤规则。
  • 限制深度与大小：设置maxdepth、maxrefs、maxbytes防止DoS。
  • Look-Ahead模式：在反序列化开始前检查类元数据，而非在对象构造后检查。
  • 替代方案：考虑使用JSON/Protobuf等更安全的数据格式替代Java原生序列化。

🔍 根因分析

Java原生反序列化机制在ObjectInputStream.readObject()执行时会自动调用被反序列化对象的readObject()、finalize()等方法。攻击者可构造特殊的对象图（Gadget Chain），使得在反序列化过程中触发任意代码执行。本例中缺乏输入验证，导致攻击者可通过上传恶意序列化数据实现RCE。

🛡️ 防御总结

  • 使用ObjectInputFilter实现基于白名单的类过滤（Java 9+）。
  • 设置合理的深度（maxdepth=20）、引用数（maxrefs=100）、字节数（maxbytes=1048576）限制。
  • 对所有用户可控的序列化数据入口实施过滤，不得遗漏任何readObject()调用点。
  • 考虑迁移至类型安全的序列化方案（如Jackson的enableDefaultTyping限制、或完全避免多态反序列化）。
