教师登录态 · 全链路开发规格

重构教师工作台与课程中心

这是一份可直接交给开发 Agent 执行的完整任务规格：把教师首页改造成跨课程工作台，统一课程概览、课件、题目、演示、学情的导航与内容生命周期，并用结构化任务契约、逐题子任务和确定性验收修复“五题变一题”。示意图只解释目标层级，工作包、接口约束与验收场景才是实现依据。

核心决策

实现必须同时统一课程中心信息架构、内容状态模型与生成任务契约；只改样式、只换文案或只补提示词，都不算完成。

01 / PRODUCT DIAGNOSIS

问题不是“不好看”，而是首页职责错误

依据真实教师登录态，检查桌面 1440 × 900 与移动端 390 × 844。

当前

教师登录后看到上一条长对话

旧会话、空对话和模型输出占据首屏；待办、失败任务、最近课程与学生风险不可见。

目标

教师登录后看到跨课程工作台

先呈现“需要我处理、AI 任务、最近课程、学情变化”，再通过带上下文的 AI 指令栏发起工作。

P0 五题被合并为一题

生成前没有确认“5 道独立题”，生成后没有核对“目标 5 / 实际 1”。

P0 课程上下文不持续

会话标题无法稳定说明课程、章节和产物，写入目标难以核对。

P0 任务完成状态失真

抽屉只给出 100% 与“定位到对话”，看不到目标数量、失败项和结果审核。

P1 会话历史被噪声淹没

大量同名和空对话让工作记录退化为运行日志。

P1 课程卡只有库存数字

章节、题目、学生数量不能回答“现在应先处理哪门课程”。

P0 移动端存在真实阻断

快捷操作被裁切、CTA 竖排；屏外侧栏仍进入键盘焦点顺序。

审计结论

视觉样式已经较统一，但同一对象存在“课程页签、独立管理页、AI 会话、生成任务页”四套入口；主操作重复、状态口径不同、详情缺少课程上下文。教师必须先理解系统结构，才能完成本应围绕课程内容展开的工作。

页面 / 流程真实体验问题与原因开发决策
课程列表
P1 · 决策效率		 课程卡主要展示章节、题目、学生等库存数字；整卡和“进入课程工作台”重复跳转，编辑与删除常驻暴露。教师无法按待审核、失败、风险或最近工作决定先做什么。 增加搜索、状态过滤、最近工作和待处理信号；整卡保留一个主入口，编辑/删除进入更多菜单；课程数字必须标明统计范围。
课程概览
P1 · 层级		 “全部课程 / 切换课程”语义重复；完成率没有分母、时间范围和趋势；课程动态常为空；课程码与设置占据与教学决策同级的位置。 首屏改为课程待办、发布准备度和有定义的关键指标；课程码降为辅助信息；没有事件事实时不保留空的“课程动态”面板。
课件管理
P0 · 心智模型		 “输入资料”和“输出课件”并列，但空状态把资料称为课件；上传资料、AI 生成课件和打开 AI 助手重复分散。列表没有章节归属、来源到产物的血缘、更新时间和待审核状态。 建立“原始资料 → 课件草稿 → 版本 → 发布”的可见链路；每页只保留一个主创建入口，入口内再选择上传资料或 AI 生成。
课程题目页签
P0 · 重复入口		 页首、区块标题和每个章节重复“新建题目”，同时存在页内管理模式与独立题目管理页。空章节逐个展开，页面随章节数线性变长；题目行缺少草稿、验证、发布、尝试和更新时间。 题目页签成为唯一主工作区；一个“新建题目”菜单承载手工、AI 批量、导入；章节默认可折叠，统一工具栏切换排序管理模式。
题目管理 / 题库
P0 · 双重产品		 独立页先显示大型统计 Hero，再进入题库；列表展示完整长描述，桌面密度高，移动端列表和详情整页串联。课程页显示 6 道而题库显示 10 道，但没有说明前者是已发布、后者是全部。 移除第二套 Hero 与导航；复用课程壳层。统计统一返回 total/draft/published/needsReview；移动端列表与详情分步打开，列表摘要限制行数。
AI 出题与生成任务
P0 · 结果可信度		 结构化 AI 出题页已支持数量 1–5，但与自然语言智能体分离；任务页暴露原始长提示词、内部流水线和重复 100%，教师看不到目标数量与真实产物的直接核对。 两种入口共享同一批次契约与审核页；任务默认只显示教师目标、阶段、requested/created/validated/failed 和下一步，调试细节只向管理员按需展开。
演示管理
P0 · 动作歧义		 “生成攻防演示”和“AI 生成演示”并列但差异不清，又叠加区块和逐章节新建入口。列表没有缩略预览、教学目标、预计时长、可上课状态；大量空章节产生重复空状态。 保留一个“新建演示”，先选择攻防演练或交互模拟并解释用途；卡片补充预览、目标、时长、状态和更新时间，空章节默认折叠。
学情
P1 · 数据解释		 证据覆盖提示较完整，但面板密集、行动名单靠后；基于极少测评的数据可能显示 1% 等高精度结论。题目管理里的“质量与学情”又复制一套指标入口。 学情成为课程唯一分析入口；先显示需干预对象和建议动作，再展示趋势与维度；置信度、样本数和时间范围必须与分数同屏。
手工新建题目 / 章节
P1 · 流程成本		 简单章节表单也套用三步仪式与大面积预览；复杂题目表单则是单页长表，步骤条没有真实分步，保存按钮在页面底部。浮动“改用 AI 助手”覆盖右侧预览。 简单对象使用紧凑表单；复杂对象才使用真实分步或分区导航。主操作粘底、自动保存；AI 变为字段内“协助填写”，不再作为覆盖内容的替代入口。
课件 / 演示详情
P1 · 上下文		 预览壳层清晰，但只有通用“调整与版本”；缺少课程/章节返回路径、来源资料、版本差异、发布对象、学生视图和下一步主操作。 详情页固定展示面包屑、生命周期、来源血缘、版本历史、学生预览与发布动作；返回时保留原筛选和滚动位置。
移动端
P0 · 可完成性		 没有横向溢出，但题目/演示因逐章节 CTA 变成超长页面；题库把统计、列表、详情全部纵向堆叠；题目新建页超过 3000px，主操作直到末尾才出现。 移动端使用“列表 → 详情”单任务模式；工具栏粘顶、主操作粘底；章节折叠且只在当前章节显示创建入口，筛选进入底部抽屉。
导航模型分裂

课程页签、独立管理页、AI 会话与任务页各自建立入口和统计，导致教师在系统结构之间跳转。

状态模型不可见

草稿、验证、待审核、发布和失败没有贯穿列表、详情与任务，UI 只能用模糊数字补位。

操作层级失控

全局、页面、区块和章节级 CTA 同时出现；主操作越多，教师越难判断哪个入口最安全。

对象关系被切断

资料、课件、版本、题目批次和演示之间缺少来源与归属，详情页成为脱离课程的孤岛。

数据缺少口径

“6 道”和“10 道”可能都正确，但未注明已发布/全部；低样本指标仍呈现高精度，削弱可信度。

桌面布局被直接压缩

移动端虽不溢出，却把全部桌面信息串成长页，没有转化为更聚焦的任务流。

OVERVIEW

课程概览：显示准备度与下一步

  • 首屏顺序固定为待处理、发布准备度、课程进度、最近活动。
  • 完成率必须带分母、时间范围、定义和趋势；证据不足显示“暂无足够证据”。
  • 章节列表显示课件/题目/演示的已发布与待处理数量；课程码和设置降级到辅助区。
  • 课程动态只能来自真实事件；无数据时改为起步建议，不显示永久空框。
COURSEWARE

课件：让资料到发布的关系可追踪

  • 一个主按钮“新建课件”，菜单内选择上传资料、从资料生成、从空白创建。
  • 按章节分组并支持搜索、状态/来源过滤；显示原始资料、派生产物、版本、更新时间和负责人。
  • 资料行与产物行使用明确类型和动作；删除进入更多菜单并展示影响范围。
  • 生成完成进入待审核，不自动发布；详情可回到原筛选与章节。
QUESTIONS

题目：合并题库、AI 出题与审核

  • 题目页签是唯一主工作区；页首显示全部、草稿、已发布、需处理四种有口径计数。
  • 一个新建菜单承载手工创建、AI 批量、导入/复用；自然语言与表单共享 batch contract。
  • 章节可折叠；列表摘要最多三行，详情在侧栏或独立深链；工具栏统一切换排序管理。
  • 生成任务只显示摘要和结果入口；质量问题下钻到学情，不复制完整分析首页。
DEMOS

演示：先选教学形态，再进入编辑

  • 一个“新建演示”打开类型选择：攻防演练、交互模拟；说明适用场景、预计准备成本和学生体验。
  • 卡片展示缩略预览、教学目标、时长、章节、版本、发布状态和最后编辑。
  • 支持预览、复制复用、移动章节、版本和发布；危险操作进入更多菜单。
  • 空章节默认折叠，提供当前章节的单一创建入口。
LEARNING

学情：唯一分析入口，先行动后解释

  • 首屏优先呈现需干预学生、停滞任务和可执行建议；总览图表排在行动队列之后。
  • 所有分数同屏展示样本数、覆盖率、时间窗和置信等级；低样本不显示虚假精确百分比。
  • 支持章节、题目、学生和时间过滤，筛选状态写入 URL 并可分享。
  • 题目质量作为学情下钻，不在题目管理建立第二套分析主页。
CREATE / EDIT

创建：复杂度决定页面形态

  • 章节等简单对象使用紧凑表单；只有存在真实跨步依赖时才使用步骤器。
  • 长表单提供分区导航、自动保存和粘底主操作；离开时提示未保存改动。
  • AI 作为字段级“协助填写/基于资料生成”，保持课程与章节上下文，不使用遮挡预览的浮动入口。
  • 保存草稿、验证、发布是明确不同动作，发布前必须学生安全预览。
DETAIL / VERSION

详情：让上下文、版本和发布同屏

  • 固定面包屑“课程 / 章节 / 对象”，返回时恢复列表筛选、分页和滚动位置。
  • 页首同时展示对象类型、当前版本、生命周期、学生可见性和唯一下一步动作。
  • 版本面板展示来源资料、生成任务、差异、作者与时间；允许预览历史版本但只发布一个有效版本。
  • 学生视图必须隐藏标准解、Flag 与教师备注，并与真实学生权限使用相同序列化边界。
CONTENT MODEL

统一对象与计数语义

  • 资料 → 课件草稿 → 课件版本 → 已发布版本；批次 → N 个题目草稿 → 验证 → 审核 → 发布。
  • 所有计数返回 total/draft/published/needsAttention，页面不得自行从不同集合推导。
  • “课程有 6 道题”必须写成“已发布 6 / 全部 10”，并允许下钻到相同过滤结果。
  • 列表、详情、任务中心和工作台使用同一状态枚举与显示映射。
05 / IMPLEMENTATION BRIEF

实施范围、约束与交付要求

本节定义开发边界；后续工作包定义具体改动。

实施建立在现有玄甲全局智能体、课程事实和持久任务模型之上。工程顺序固定为“批量正确性 → 统一状态/计数 → 路由与课程壳层 → 各内容工作区 → 创建/详情 → 移动端与端到端验收”，每一阶段均须提交可自动复核的证据。

目标结果

产品要求

  • R-01：直接访问 /teacher 且未指定会话时显示跨课程教师工作台，不自动恢复旧对话。
  • R-02：工作台首屏包含“需要我处理、AI 任务、最近课程、学情变化”和带课程/章节上下文的 AI 指令栏。
  • R-03：教师明确要求 N 道独立题时，生成前确认 N，执行时创建 N 个独立子任务，结果页验收 N 个独立题目事实。
  • R-04：生成计划可修改；未确认不写课程；审核前草稿对学生不可见；失败子项可独立重试。
  • R-05：任务中心显示真实阶段、数量、失败项与结果入口，刷新和重新登录后状态一致。
  • R-06：320–430px 下主操作完整可见，关闭侧栏不再接收键盘焦点。
  • R-07：课程概览、课件、题目、演示、学情共享同一课程壳层、面包屑、上下文和返回行为。
  • R-08：每个工作区只有一个主要创建入口；页面、区块和逐章节不得重复同语义 CTA。
  • R-09：课程列表、概览、题库和工作台使用一致的 total、draft、published、needsAttention 计数口径。
  • R-10：课件展示资料来源、派生产物、版本、章节、审核和发布关系；详情可追溯来源。
  • R-11：题目页签合并题库、AI 批量、排序管理与审核；旧题目管理 URL 只作为相同工作区的兼容深链。
  • R-12：演示创建先选择攻防演练或交互模拟，列表显示预览、目标、时长、版本和可上课状态。
  • R-13：学情是课程唯一分析入口；分数必须与样本数、覆盖率、时间窗和置信等级同屏。
  • R-14：创建页按真实复杂度选择紧凑表单或分步流程，支持自动保存、粘底操作和离开保护。
  • R-15：课件、题目和演示详情持续显示课程/章节、版本、学生可见性、来源血缘和学生安全预览。
  • R-16：移动端使用列表到详情的单任务流，章节可折叠、筛选进抽屉、主操作粘底，不能只是把桌面内容纵向堆叠。

工程要求

  • E-01：复用 teacher-agent、teaching API、GlobalAgentTask 和 challenge authoring，不建立第二套出题应用。
  • E-02：课程、章节、题目、发布和验证状态继续以玄甲持久事实为唯一来源。
  • E-03：requestedCount 与 independence 在教师确认后不可被模型、重试或恢复流程静默修改。
  • E-04：批次执行和单项重试具备幂等性；成功子项不因兄弟任务失败而被覆盖或重复创建。
  • E-05：保留既有权限、审批、动态 Flag、标准解验证和学生发布隔离边界。
  • E-06：任务成功由真实子任务和产物计数确定；模型答复与前端百分比不参与终态判定。
  • E-07：为课程壳层建立共享 view model / API DTO，统一上下文、状态枚举、计数、权限和下一步动作。
  • E-08：保留旧 URL 兼容性并执行可测试的重定向或深链映射；不得同时维护两套题目管理 DOM 与业务逻辑。
  • E-09：资料、产物、版本、生成批次和发布记录使用稳定 ID 关联；列表不能依赖标题或数组位置拼接关系。
  • E-10：所有统计由服务端同一查询口径生成，响应附带 scope、asOf 与 evidenceCount；前端只格式化不重算。
  • E-11：原始提示词、模型路由、内部阶段名和作者 ID 默认不进入教师 UI；仅管理员调试视图可按需查看并脱敏。
  • E-12：共享组件满足键盘、焦点、语义状态、减少动效、200% 缩放和 320px 最小宽度要求。
数量约束属于服务端

模型负责理解内容，服务端负责保证 requestedCount 与独立题目数量一致。

首页只展示真实聚合

待办、任务和风险必须来自持久 API；没有数据时显示空状态，不使用示意数字。

保留单一全局智能体

工作台、课程入口和 AI 共创共享同一会话与任务模型，不另建“AI 出题中心”。

一个对象一个工作区

题目、课件、演示不得再由互不一致的页签与独立管理首页同时承担主入口。

状态先于展示文案

先统一服务端状态与转移规则，再映射界面标签；页面不可用“完成 100%”猜测业务终态。

发布边界不可弱化

任何 AI 或手工产物都先成为教师草稿，经过验证、审核和学生安全预览后才能发布。

明确不在本轮扩张的范围

不重写学生学习工作区、不替换 CTFd/现有 API 技术栈、不新建第二个 Agent 或题库后端、不做脱离任务流程的品牌视觉翻新。允许为学生安全预览和发布隔离补充只读契约，但不得借此扩大为学生端全面重构。

EXECUTION ORDER

实施顺序与交付物

  4. 完成 WP06 的共享课程 view model、状态/计数口径和兼容路由，再改造任何单独页签。
  5. 完成 WP03–WP04 的工作台与任务中心，使课程待办和内容状态能够跨页面恢复。
  6. 按 WP07 课件、WP08 题目、WP09 演示、WP10 学情、WP11 创建与详情逐域迁移；每完成一域就删除对应重复入口和旧 DOM。
  7. 最后执行 WP05 与 WP12 的移动端、无障碍、性能和全链路回归；根据失败继续修复，直至完成定义全部满足。

  • 旧题目管理路由兼容映射、旧入口移除清单，以及不再双写/双算的代码证据。
  • 数量归一化、状态迁移、统计口径、版本血缘、权限、幂等和部分成功的自动化测试。

WP01 建立批量出题的持久任务契约先修正确性；这是其他 UI 改造的前置依赖

实现步骤

  • 在模型规划结果进入执行器前，统一解析中文数字、全角数字和阿拉伯数字；显式题量优先于模型默认值。
  • 教师确认后持久化批次契约；保存课程、章节、题型、目标数量、独立性、难度策略和幂等键。
  • 先生成恰好 N 个题目规格，再为每个规格创建独立子任务；每个子任务保存稳定的 itemIndex 和独立草稿标识。
  • 队列恢复、失败重试和人工续跑只能读取原批次契约，禁止重新从自然语言猜数量。
  • 聚合器按真实子任务计算 createdCount、validatedCount 和 failedCount；小于目标数量时禁止进入 completed。

失败与恢复规则

  • 五个子任务之一失败时，批次进入 partial_success，其余成功草稿继续可审核。
  • “只重试失败项”复用原 itemIndex 和题目规格，不创建新的兄弟任务。
  • 用户取消批次时只取消仍在运行的子任务，不删除已经生成的草稿。
  • 超过单批上限时在确认前明确阻止执行，不得静默截断为五道或一道。
  • 并发创建时用批次幂等键和 itemIndex 唯一约束防止重复题目。

WP02 增加生成前确认与生成后审核把模型理解转换为教师可核对的任务计划

确认卡

  • 持续显示课程、章节、产物类型、题目数量、独立性和难度分布。
  • 展示五个拟生成题目的标题或能力目标；教师可在执行前修改。
  • 主按钮必须写为“确认并生成 5 道题”，不能只写“继续”或“确认”。
  • 未经确认，不创建任务、草稿、环境或学生可见事实。

审核页

  • 逐题显示标题、难度、技能、草稿状态、环境状态和标准解验证结果。
  • 支持逐题预览、修订、重试、删除和发布，也支持批量修订与批量发布。
  • 页首固定显示“目标 5 / 已创建 5 / 已验证 4”，禁止用模糊百分比替代。
  • 发布前再次显示目标课程和章节；学生只读取已发布的有效版本。
WP03 把 /teacher 改造成教师工作台默认登录落点负责跨课程决策，而不是恢复随机旧会话

页面行为

  • 直接访问 /teacher 且未指定 thread 时显示工作台；选择会话或任务后再进入对话视图。
  • 首屏依次展示“需要我处理、AI 任务、最近课程、学情变化”；每一项都有明确下一步。
  • AI 指令栏在提交前展示当前课程/章节；无上下文的写操作必须先选择或澄清范围。
  • 工作台空状态提供真实的起步操作，不自动打开最后一条长对话。

数据规则

  • “需要我处理”只包含 waiting_confirmation、needs_review、partial_success、failed 和真实学情异常。
  • “AI 任务”只包含 queued、generating 和 validating，显示真实阶段和数量。
  • “最近课程”按教师最近有效操作排序，显示待处理数量与继续工作入口。
  • 后端数据缺失时展示空状态或不可用说明，不在前端推测完成率和风险。
WP04 统一任务中心与会话治理任务结果优先于聊天过程；空会话不再污染历史

任务中心

  • 任务卡显示课程、章节、教师目标、requested/created/validated、真实耗时和下一步。
  • 完成后的主操作是“审核结果”或“打开产物”，不再只提供“定位到对话”。
  • 刷新与重登后从持久任务和事件恢复状态；模型消息不是状态来源。

会话治理

  • 新对话在发送第一条有效请求后才持久化；空白或取消输入不落库。
  • 首轮计划形成后按“课程｜动作｜对象”命名，例如“软件安全｜生成 5 道逆向题”。
  • 同一批次的修订、重试和发布复用原会话；允许按课程、任务类型和状态筛选。

WP06 统一课程壳层、路由、状态与计数所有课程页面的前置依赖；先统一事实，再迁移界面

08 / MOBILE & ACCESSIBILITY

移动端重新编排，不再挤压桌面布局

01

关键操作首屏可见

快捷操作最多展示两个，其余进入“更多”；不裁切、不制造无提示横向滚动。

02

关闭侧栏同时退出焦点树

使用 inert 管理屏外侧栏；关闭后 Tab 不得进入任何不可见会话。

03

主操作保持完整横排

课程 CTA 使用全宽按钮；编辑、删除收进更多菜单，触控目标建议不小于 44 × 44。

04

任务可离开、可恢复

切换课程或关闭页面后，进行中、部分成功和待审核状态保持一致。

05

列表与详情分步

题目、课件和演示列表不再把完整详情堆在其后；打开详情后提供明确返回，并恢复筛选与滚动位置。

06

章节默认折叠

仅展开当前或包含待处理项的章节；创建入口属于当前上下文，不为每个空章节复制。

07

长表单操作粘底

保存草稿、验证和下一步始终可达，并避开安全区；软键盘打开时不遮住当前字段与错误。

08

筛选使用抽屉

页签可水平滚动但当前项始终可见；复杂筛选进入有焦点管理的底部抽屉，结果数量即时反馈。

ROLLOUT & MEASUREMENT

灰度发布与效果验证

先证明事实一致与任务可完成，再根据真实基线验证效率提升。

发布顺序

  1. 先上线只读统一 DTO、状态映射与计数对账日志，不改变页面；在两类真实课程上消除统计差异。
  2. 批量契约与新课程壳层分别置于服务端功能开关后；先开放给内部教师和测试课程。
  3. 逐域启用课件、题目、演示、学情；每一域达到验收门槛后才重定向旧入口。
  4. 至少一个稳定观察周期无 P0 回归后，移除旧 DOM、重复请求和功能开关；数据库迁移保留可回滚路径。

成功指标与护栏

  • 硬正确性：1–5 题数量契约自动化通过率 100%；跨页面计数差异、草稿泄漏和旧深链失效均为 0。
  • 任务效率：以改造前同任务基线为对照，课程进入到“可审核草稿”的中位时间降低至少 20%，无效往返导航降低至少 30%。
  • 可完成性：内部可用性测试中，教师无培训完成上传课件、AI 五题、创建演示、查看风险四项任务的成功率不低于 90%。
  • 移动护栏：390px 关键任务成功率与桌面差值不超过 10 个百分点；前端错误率、API p95 和发布失败率不得劣化。
  • 埋点只记录对象类型、稳定 ID、状态、耗时和入口，不记录题干、答案、Flag、原始 prompt 或学生敏感内容。
ACCEPTANCE GATES

上线门槛

  • 明确要求 N 道，必须创建 N 个独立题目事实1–5，道数与自然语言完全一致。
  • 一题失败时显示 4/5，而不是 100%仅重试失败项不会复制其余结果。
  • 确认前不写课程事实审核发布前学生不可见。
  • 同一计数在所有页面含义一致全部、草稿、已发布、需处理可下钻到相同对象集合。
  • 题目只有一个主工作区旧 URL、课程页签和任务结果打开相同壳层与题目事实。
  • 资料、产物与版本可双向追溯课件和演示详情能回到来源、课程与章节。
  • 登录后无需打开旧对话即可决定下一步待办、任务、最近课程首屏可见。
  • 390 与 320 像素宽度无主操作裁切课程 CTA 不竖排，快捷入口可发现。
  • 关闭侧栏后 Tab 不进入屏外控件键盘完成任务审核与发布流程。
  • 每个工作区只有一个主创建动作页首、区块和空章节不重复同语义 CTA。
  • 学情结论说明证据强度低样本显示证据不足，不输出虚假精确分数。
  • 学生预览使用真实权限边界标准解、Flag、教师备注和内部任务信息不可见。
EXECUTABLE SCENARIOS

必须自动化的验收场景

每个场景都要验证持久事实和浏览器可见结果，不能只断言模型答复文本。

SCENARIO 01 · 五道独立题
Given
教师已进入“软件安全 / 逆向工程”，该章节当前题目数记为 B。
When
教师输入“一次生成五道彼此独立的动态 Flag CTF 题”，选择方案并确认。
Then
批次 requestedCount=5；存在五个不同 taskId、draftId、itemIndex 和题目入口；章节题目事实变为 B+5；不存在用单题五关满足数量的结果。
SCENARIO 02 · 部分失败与单项重试
Given
五个子任务中四个验证通过，一个因环境构建失败。
When
批次聚合完成，教师点击“只重试失败项”。
Then
页面与 API 均显示 4/5 和 partial_success；只新增或恢复失败项的执行，四个成功 draftId 保持不变；重试通过后批次进入 needs_review，而不是自动发布。
SCENARIO 03 · 登录工作台
Given
教师有多门课程、待审核草稿和一个运行中任务，历史中存在旧会话。
When
教师重新登录并直接访问 /teacher。
Then
默认显示工作台而不是旧会话；待审核项、运行任务和最近课程来自 API；点击某项后打开对应会话或产物，课程/章节上下文保持一致。
SCENARIO 04 · 移动端焦点与布局
Given
浏览器视口为 390 × 844 或 320 × 568，会话侧栏处于关闭状态。
When
用户依次按 Tab，打开并关闭侧栏、任务抽屉，再查看课程卡。
Then
焦点只进入当前可见控件并正确归还；页面无水平溢出；主 CTA 不竖排；快捷操作、错误状态和任务数量均可见。
SCENARIO 05 · 数量表达归一化
Given
教师分别使用“5 道”“五道”“５道”“生成三题”等明确数量表达。
When
规划器形成生成方案并提交任务契约。
Then
requestedCount 分别为 5、5、5、3；模型若返回不同数量，服务端拒绝执行并要求重新规划，不静默采用模型值。
SCENARIO 06 · 回归边界
Given
现有单题生成、批量修订、发布、课程权限与学生预览流程可用。
When
批量契约和工作台改造上线。
Then
单题仍只创建一个任务；未发布草稿对学生不可见；跨课程写入被拒绝；动态 Flag 和标准解验证仍按原安全边界运行。
SCENARIO 07 · 题目主工作区归一
Given
同一课程可从课程题目页签、旧题目管理 URL、任务结果和智能体结果进入题目。
When
教师分别从四个入口打开题目库或同一个 draftId。
Then
均进入同一课程壳层与题目工作区；选中对象、过滤和统计一致；页面不存在第二套 Hero、页签或重复创建按钮。
SCENARIO 08 · 计数口径一致
Given
课程有 10 道题，其中 4 道草稿、6 道已发布、1 道需处理。
When
教师查看课程卡、课程概览、题目工作区和工作台待办。
Then
所有位置分别显示相同口径且带标签；点击“已发布 6”得到恰好 6 个对象，点击“全部 10”得到恰好 10 个对象，响应 scope 与 asOf 一致。
SCENARIO 09 · 课件来源与发布
Given
教师上传一份资料，并据此生成课件草稿 v1。
When
教师打开课件详情、预览、修订为 v2 并发布。
Then
资料、生成任务、v1、v2 和课程章节可双向追溯；发布前学生不可见，发布后只看到 v2；返回列表恢复原筛选与滚动位置。
SCENARIO 10 · 演示类型选择
Given
课程演示页同时支持攻防演练和交互模拟。
When
教师点击唯一“新建演示”，选择一种类型并创建草稿。
Then
类型选择器明确展示差异；后续表单只出现该类型所需字段；列表卡显示预览、目标、时长、版本和状态，不再出现两个同义 AI CTA。
SCENARIO 11 · 低证据学情
Given
某课程只有一名学生的一次有效测评，证据覆盖不足。
When
教师打开课程学情和题目质量下钻。
Then
页面显示样本数、时间窗和低置信提示，不用 1% 等精确数字暗示确定结论；题目管理不再出现第二套“质量与学情”首页。
SCENARIO 12 · 移动端创建题目
Given
视口为 390 × 844，教师从逆向工程章节手工新建题目。
When
教师填写长表单、触发校验、打开软键盘、保存草稿并返回。
Then
课程/章节上下文持续可见；主操作粘底且不遮挡字段；错误聚焦到对应区块；返回后题目列表恢复章节、筛选和滚动位置。
SCENARIO 13 · 学生安全预览
Given
某题目或演示草稿包含标准解、动态 Flag、教师备注和内部生成信息。
When
教师打开“学生视图”，并分别以教师和学生身份请求对象接口。
Then
学生预览与学生接口均不包含私有字段；教师详情保留审计信息；发布只改变有效版本与可见性，不复制对象。
SCENARIO 14 · 数据规模与空状态
Given
分别准备 0、1、6、100 个课件/题目/演示，以及超长标题和描述。
When
教师在桌面、390px 和 320px 下浏览、过滤、分页、展开章节和打开详情。
Then
空状态给出一个相关动作；空章节默认折叠；100 项不静默截断；长文不挤掉状态和主操作；页面无水平溢出和不可达控件。

Definition of Done

  1. 代码、迁移和 API 契约完成；首页、课程中心、计数与学情没有使用前端假数据或重复计算满足展示。
  2. 数量解析、批次聚合、幂等重试、状态转移、统一计数、版本血缘和学生序列化的单元/API 测试通过。
  3. 真实模型、真实队列、真实教师浏览器完成五题生成、部分失败恢复、审核和发布闭环。
  4. 课程列表、概览、课件、题目、演示、学情、创建与详情均完成新壳层迁移；旧题目 URL 只映射到同一工作区。
  5. 重复 Hero、重复主 CTA、重复学情首页、教师可见原始 prompt 和失去调用方的旧分支已移除，并记录删除清单。
  6. 资料到课件版本、批次到 N 个题目、演示到发布版本可追溯；未发布内容和私有答案对学生不可见。
  7. 0/1/6/100 项、无数据、低证据、失败、重试、刷新与重新登录场景均通过自动化验收。
