# 检查工具"做了两遍都过不了"：判定过严 + 提示无用（2026-09-23）

## 学生反馈

截图：客户端跑完检查后弹窗
`ERROR / Method 1: preserve the original program and patch its authentication condition or comparison result.`
学生已"做了两遍"，控制台里能看到自己在 `fc` 对比 `demo-patched.exe`、`method1-new.exe` 与原始文件。

## 原因（两层，都真实存在）

### 1. 判定过严：只认 5 组固定字节

旧 `verifier.py` 把学生交上来的 `method1.exe`/`method2.exe` 与 **5 个固定字节序列**逐一比对，
必须完全相等才算通过：

| 方法 | 旧判定接受的唯一写法 |
| --- | --- |
| 反转条件跳转 | `75` → `74`（只认这一个字节） |
| NOP 掉跳转 | `90 90`（只认这两个字节） |
| 直接跳到成功分支 | `EB 00`（只认这一个编码） |
| 改掉比较结果 | `33 C0` 或 `31 C0` |

题面写的是"例如……"（邀请等价做法），但学生只要用**语义完全相同、编码不同**的改法就会被拒：
实测 `2B C0`（`sub eax,eax`）、`B8 00 00 00 00`（`mov eax,0`）、近跳转 `0F 84 …` 全部被判"不通过"，
而且报的是同一句笼统的英文提示，学生完全不知道差在哪。

### 2. 提示无用：最常见的失误没有对应提示

`submit.exe` 只把 `method1.exe`/`method2.exe` 交给判定器；如果学生把改动**存成了别的文件名**
（截图里的 `method1-new.exe`）或忘了"保存文件"，交上来的就是**未改动的原始副本**。
旧判定对这种最常见的情况也回同一句话，学生无从判断"我到底改没改上"。

（另：实测 QEMU 10.1.5、客户机、串口传输都正常；`demo.exe` 本来就不参与判定，不是原因。）

## 修复

### 判定改为"看行为 + 只看最小改动"（`output/win2000/image/verifier.py`）

- **行为**：错误密码必须走到成功分支（4 组随机/固定错误密码各验一次）；据此再用原始密码判断
  是"反转条件"还是"强制成功" —— 不再依赖某一种机器码写法。
- **最小改动**：与 `crackme-original.exe` 比较，文件大小必须相同、改动字节 ≤ 8 个、且全部落在
  认证代码区间（RVA 0x15E2–0x1658）内；改多了直接拒绝并说明。
- **方法分类**（用于"两种方法必须不同"）：比较结果被改 / 条件跳转被 NOP / 条件跳转变成无条件跳转 /
  条件反转（按行为判定，任何编码都算）/ 其它等价自定义改法；同一类算同一种。
- **提示改成中文、可执行**：
  - 与原始文件完全相同 → "还没有做任何修改；请确认改动已保存到这个文件名"（直指截图里那种情况）
  - 改动超出认证判断 → 明确说明改了多少字节
  - 补丁没生效 / 程序跑不到分支 / 两份用了同一种方法 → 各自单独提示
  - 模拟执行异常（`UcError`）也被兜住，不再变成一句"Verification failed"。

### 题面补上判定标准（`data/dojos/003a97d0/dojo.yml` + `dojo_challenges.description`）

在"获取并提交 flag"前加了"检查工具怎么判定（先看这里，避免白做）"：只判定 method1/method2、
只能改认证判断附近的少量字节、两份必须不同类、保存后先自测、以及"提示与原始文件完全相同说明没保存上"、
"上一次的弹窗先关掉再检查"。数据库里的描述已同步更新，**学生无需重置**即可看到。

| 学生做法 | 结果 |

（此前旧判定对第一种组合是拒绝的 —— 即学生"做了两遍"也过不去的那种。）

### 不重置学生环境（本次专门核对）

- 平台「重启」只重建容器、**保留客户机磁盘**：实测在客户机里放好三个工作副本并跑出 flag 后，
  用新镜像（含新判定器、新 QEMU 参数）重建容器，重启后客户机状态快照仍是
  `probeMask: 15`（demo/method1/method2 均已改动、flag.txt 仍在），**学生改动与 flag 全部保留** ✓。
- 本次修复没有触碰任何学生磁盘数据：判定器只在学生点检查时读取他们交上来的字节；
  题面更新只改数据库里的描述文本；新增的共享剪贴盘是新增文件，不写学生磁盘。
- 已在运行的学生容器不会自动重启；他们**下次启动/点「重启」**即用上新判定器，进度不丢。
  已经卡住的学生：重启后重新运行检查工具即可，之前改好的方法1/方法2 原样还在。
