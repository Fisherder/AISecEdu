# 仿真生成与局部编辑重构：调研、诊断与实现

## 目标与范围

从一句话生成完整、可操作、教学内容可信且具有清晰视觉层次的成品；后续只修改指定内容，遇到模型、结构或浏览器检查失败时恢复工作而不是重做全部内容。保留现有身份、权限、课程、版本存储、隔离运行环境和发布检查。

本次源码快照来自 `/srv/aisecedu-dojo`，本地基线提交 `4770b66`。服务器有大量既有未提交变更，因此只交付本次差异，并在部署前核对源文件基线。外部代码用于研究设计，未复制第三方实现代码。

从最新12份调用检查点检查到的具体问题：

- 太阳系场景：水星在40秒被木星/土星遮挡；电动机场景：线圈、电刷和输出轴被外壳或其他构件遮挡。问题来自实际浏览器射线证据，不应通过删除focus或降低检查标准规避。
- 二分查找：数次输出出现非整数/越界下标、表达式过深及JSON结构错误。引擎的div保留小数，却缺少floor，模型容易生成错误索引。
- 讲解审校：缺少部分可见节点的审查条目；旧错误只说“Review must score every visible node”，未列出缺失ID。
- 三维修订入口没有接入call checkpoint / stage state，未传递模型调用stage且输出预算比新建小；任何调整进入导演、全场审查和完整讲解流程。
- 多作品修订对全部作品逐个执行，缺少明确的目标作品选择。
- 场景内部补丁虽然存在，却缺少用户修订专用的范围锁定、底稿指纹、原值比较和差异验收。

## 外部实现研究与取舍

### MAIC-UI

查阅仓库树 `aad58ddcc2103058b4c2deffc48a3c13e2c64dd6`，实际读取 `backend/src/services/html_generation/heavy_generator.py` 与 `backend/src/services/modify.py`。HeavyGenerator将内容对齐与视觉完善分开，并分别执行验证、有限修复和缓存；modify实现Unified Diff、上下文匹配与错误返回。参考阶段分工及差量编辑；本项目已有SceneIR，采用稳定ID的结构化补丁，避免HTML行号与模糊匹配造成误改。其应急模板降级不适合作为本项目生成成功的替代证据。论文的迭代延迟结论属于其系统，不移植为本项目性能承诺。[源码](https://github.com/THU-MAIC/MAIC-UI)，[论文](https://arxiv.org/abs/2604.25806)

### Aider

Aider区分whole、diff、udiff和architect/editor格式；whole每次输出完整文件，diff只输出变化部分。参考“规划负责解决范围，编辑器负责准确应用”以及避免无关内容重写。Aider关于不同编辑格式的评测针对特定模型/任务，不构成本项目模型的成功率保证。这里输入是JSON中间表示，选择expected原值和稳定ID，而非把代码补丁格式直接塞进JSON。[编辑格式](https://aider.chat/docs/more/edit-formats.html)，[Unified Diff研究](https://aider.chat/docs/unified-diffs.html)

### LangGraph

研究官方持久化与错误恢复设计：保存完成步骤，恢复时复用成功前缀；区分服务中断与内容修复，明确重试边界。项目已有持久化任务调度和原子文件检查点，故新增可复用的durable-stage并接入现有存储，不引入第二套队列或双重状态权威。检查点保存的是候选和阶段结果，浏览器与最终验收仍执行。[持久化](https://docs.langchain.com/oss/javascript/langgraph/persistence)，[故障处理](https://docs.langchain.com/oss/python/langgraph/fault-tolerance)

### Anthropic：上下文工程

参考按当前步骤提供有用信息、明确而简洁的系统指令。原流程每轮携带导演、全场结构、全资产说明和旧输出，容易混淆生成与修改。新流程分离主体与时间线，编辑阶段提供锁定字段及依赖上下文；实际模型可用Schema来自代码，减少提示词与执行器协议漂移。[上下文工程](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)

### StackBlitz Bolt

阅读其开源项目定位，确认把生成内容放进真实可运行环境的重要性。此平台已有确定性播放器和独立浏览器检查服务，继续采用现有运行环境验证控件和画面，不因为模型宣称完成便提交成品。[仓库](https://github.com/stackblitz/bolt.new)

## 实现方案

### 新建流程

原始需求 → 教学导演/需求展开 → 主体、空间和材质 → 轨道、镜头、章节与覆盖映射 → 完整结构验证 → 装配/教学几何 → 浏览器证据 → 学科与讲解审查 → 确定性编译。

各生成步骤使用系统提示词、完整输入和版本的指纹保存结果。当前阶段失败只修本阶段，服务断开不计为坏内容。Schema通过不等于成品通过，后续质量门保留。选定资产的真实定义参与主体设计；编译器和播放器不由模型重写。

### 局部编辑

选择受影响作品 → 将本轮指令映射为字段范围 → 输出带baseHash/expected的补丁 → 整批原子验证 → 结构与浏览器回归 → 逐项差异验收 → 新版本。

禁止整组覆盖nodes、tracks、chapters等集合，拒绝超范围、旧值不符、重复/遗漏修改和无实际变化。节点用@id，轨道用@target:property。未选中的作品直接保留。精确文字修改不重新生成全场讲解。旧有问题单独记录，不自动扩大修改范围；也不把旧问题标记为已修复。失败候选不替换现有版本。

### 确定性修复与能力补齐

- 真实浏览器发现主体遮挡时，有限尝试其他相机方向；只接受确有证据的改进且没有新遮挡，保持实体、轨道、讲解、focus不变。无法解决则交由正常定向修复，不能伪造通过。
- 补充floor/ceil/round/abs及有限数值检查；数组索引仍严格检查，不自动钳制或静默纠正错误算法。
- 互动过程报告具体失败表达式路径、输入、状态、期望和实际结果；已有合法场景改用定点补丁，测试期望可独立修复。
- 讲解审查缺项返回具体ID，提高下一次修复的可操作性。

## 验证方法

1. 单元与协议测试：原子性、范围限制、身份稳定、旧值保护、检查点恢复、取消、错误定位和计算边界。
2. 集成测试：正式路由接入staged-v2；多作品目标选择；原版本保留；共享模型配置与服务鉴权。
3. 真实模型样例：新建三维与互动过程、精确文字/颜色/镜头调整，对未修改字段计算指纹并比较。
4. 真实浏览器：取样画面、播放/暂停/单步/复位、响应式展示与运行错误；检查来源Hash绑定候选。
5. 部署：基线Hash核对、隔离实例试运行、保存原镜像与回滚说明、正式入口验收。

截至本报告首次写入，32项新增单元测试已通过；真实模型、浏览器与部署结果在验收报告中另行记录，不能以单元测试替代实测。基线已有11项测试失败（旧fixture的泛泛声明被当前内容规则拒绝），已在独立未修改快照上复现，后续分别记录。

## 第二轮真实模型验收发现与处理

- 第一轮二分查找失败于 `concat` 参数超限，原流程在结构未通过时仍整段重写，随后引入非法 JSON。新增 `applyProcessDraftRepair`，允许对尚未通过协议的草稿原子打补丁，最终仍要求完整协议、执行测试和内容审查通过。
- 互动过程改为四阶段：输入与状态、原子操作、视图与讲解、独立测试。每一步持久化，失败时保留已完成步骤；操作表达式在本阶段就检查参数数量和变量引用。
- 第二轮暴露 `markedIndices` 用固定长度条件数组筛选下标，混入 `-1` 并越界。运行时新增通用 `indicesOf`、`range`、`concatArrays`，均保持原有128项容量限制，不引入任意代码执行；明确 `floor` 等数值操作的语义。
- 语义审查只返回问题但不给补丁时，新增独立定向修复步骤，再走原有几何和语义验收。没有降低通过标准。
- 验收脚本的 Node fetch 存在默认五分钟响应头等待上限，导致长任务的客户端提前断开；改为显式长连接 HTTP 请求。该问题属于验收脚本，不计为产品模型生成失败，正式 Python 持久任务工作器使用自己的超时预算。
- 当前相关测试52项通过。已有旧三维生成测试仍包含不符合现行学生文案协议的 fixture，以及未模拟已存在 learner-plan 阶段的 mock；已在原始基线复现，未通过修改生产校验来迁就它们。

真实样本结果将以最终构建重新验收数据补齐；以上修复和单元测试不等于线上成功率承诺。


## 后续真实验收推动的修正

- 原子动作新增有序 `locals`。动作开始时依赖前一局部量计算中间值，随后原子提交状态，避免模型反复展开旧状态表达式。局部量不能自引用、前向引用或泄漏至视图/全局条件；错误不提交半步状态。
- 新增受容量限制的数组筛选、范围、数组连接和文本 `join`。文本 `concat` 的长参数列表可以等价分组，保持原操作数顺序、空值语义和表达式验证，不猜测或修补有歧义 JSON。
- 草稿修复改用独立短协议，只输出具体字段补丁，测试原样保留。原值校验由经过校验的不可变底稿指纹确定；用户主动修订仍必须携带 `expected`，两种授权范围不混用。
- 实测发现 DNA 候选虽然通过旧自动门，却以整链分离替代了原文“局部分离”。人工验收拒绝该候选，没有计为成功。新增原文片段清单，逐项引用原文并核对具体动作；进一步在建模前独立审查实施计划，避免晚发现后整场返工。最终审查继续核对实际场景，而非以计划通过替代成品证据。
- 需求判定、计算设计和修复启用有时限的推理；大段三维结构输出仍使用直接结构化生成。推理达到90秒会进入已有服务恢复路径，不切换教师选择的模型。
- 从现有 CPU 教学作品的同一不可变版本开始，分别做标题、颜色、第二镜头修改，三次真实模型调用流程都成功；实际变化路径分别仅为 `/title`、`/nodes/4/color`、`/shots/1/position/0` 与 `/shots/1/position/1`。总耗时约79秒、158秒、257秒，包含独立浏览器和差异审查，不能把模型编辑耗时冒充完整交付耗时。
- 截至最新构建前，119项针对性单元/集成测试通过，覆盖计划拒绝后的恢复和完整检查点复用。尚未将新建样例记为最终通过，仍待真实模型与人工浏览器验收。

### 可重复验收

`ops/evaluate-simulation-workflow.mjs` 接受隔离运行时地址、服务令牌和唯一运行ID，执行 `cpu`、`binary`、`valve` 或 `dna` 请求，保存每次尝试及完整候选。它直接访问运行时集成接口，不写主站课程库；只能用于明确指定的隔离运行时。服务令牌通过环境变量提供，不记录到报告或请求文件。最终数据必须注明从头生成还是复用检查点，并保留失败次数；模型重试不算独立样本。

## 最终验收阶段的设计修正

- 提取后的需求增加独立原文核对，消除“普通重置”被扩写成“清空输入”等新增承诺。所有结构化模型调用明确 JSON 输出约定，修复供应商 `json_object` 对提示词的约束导致的400错误。
- 互动过程审查使用真实 CSS 颜色事实，消除算法正确但“灰色/高亮”说明与页面不一致的问题。新二分查找样例第一次任务执行约313秒完成；在实际编译后的浏览器引擎中穷举0–99全部合法目标值，逐步核对中点、左右边界、排除元素及最终结果。另通过6个DOM操作样例、暂停、撤销、复位、390px宽度及无运行异常检查。
- 同一二分查找作品的局部标题修改约42秒，变化路径仅 `/title`，算法、数组、标记与控件保持一致。
- 3D素材事实必须与运行时能力同时演进。DNA新增可选 `separation=local`、`separationCenter`、`separationSpan`：现有 `explode` 轨道驱动同一分子指定区域的连续骨架和相连碱基半对，不用额外副本假装局部动作。默认仍为既有整链观察行为；局部变形补齐截面随切线转动、精确复原与保守运动包络。默认场景四个时间状态与修改前的实际运行时比较一致。该能力为定性结构教学，不声称分子动力学或酶促解旋。
- 对真实浏览器确认的静止非焦点遮挡物，机位搜索之后可尝试透明观察候选。受保护教学焦点及其祖先、任何运动节点及其后代、文字面板均不自动淡化；只有真实复测减少问题且没有新增问题才采用，之后继续原文和语义验证。该步骤只用于新作品质量恢复，不扩大用户局部修订范围。
- 真实审查出现“总结章必须有新动作”“后壁不可见等于整个复合物体不可见”等误报。新工作流不再把上轮审查文字当本轮要求重复喂入；原文逐项均已实现但审查仍提出问题时，增加独立逐条证据裁定。裁定必须原样引用每一问题并给依据，缺项或重复被拒绝。真实方向、结构和可见性矛盾仍阻断交付；原文缺项直接保留，不由此步骤豁免。
- 当前针对性单元与集成测试128项通过，生产构建通过。旧资产快照测试另外发现6个基线差异：DNA旧指纹与当前基线已不一致，5个后来增加的资产未录入旧字典；默认DNA已单独与本次修改前运行时对比，没有通过更新旧指纹掩盖回归。

以上为工程验证记录。新建3D成品仍须按最终实际构建完成自动门和人工画面验收；中间失败和复用检查点后的成功应分别记录，不能将挑出的成功样例声称为总体成功率。
