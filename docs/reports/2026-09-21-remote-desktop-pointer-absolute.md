# 远程桌面鼠标不能一次移到边缘：原因与修复（2026-09-21）

## 现象

学生在 Windows 2000 桌面里移动鼠标时，指针落点与鼠标位置对不上，尤其是想移到屏幕边缘时一次到不了，
需要在桌面里反复"搓"几下才能靠近目标。

## 原因

客户的鼠标是 **PS/2 相对坐标设备**，不是绝对坐标设备。

QEMU 启动命令里没有绝对定位设备：

```
qemu-system-x86_64 ... -machine pc -cpu pentium3 ... -vga std -display none -vnc unix:...sock,password=on
```

`-machine pc` 默认只提供 PS/2 鼠标，它只上报**相对位移**。noVNC 只能根据浏览器里的指针位置与它上一次
认为的客户机指针位置去推算位移量；一旦有偏差（Windows 的指针加速、丢事件、缩放换算）就会越走越偏，
表现就是"一次移不到边缘、要来回搓"。这也是 KVM/QEMU 远程桌面的经典问题。

## 修复

给客户机加一个**绝对坐标定位设备**（USB 数位板），QEMU 的 VNC 服务会自动把指针模式切换为绝对定位，
noVNC 也会跟着切成绝对模式，鼠标落点即所见位置：

```python
"-machine", "pc", "-cpu", "pentium3", "-m", "256", "-smp", "1",
"-usb", "-device", "usb-tablet",
```

注意两点：

- QEMU 10 的 `pc` 机型**默认不启用 USB 控制器**，只写 `-device usb-tablet` 会直接报
  `No 'usb-bus' bus found for device 'usb-tablet'`，必须同时加 `-usb`。
- Windows 2000 自带的 USB HID 驱动能识别这个数位板：客户机注册表 `Enum\USB` 下已枚举出该设备，
  指针随即变为绝对定位。

## 验证

用客户机内部的 Python 读取 `GetCursorPos()`（经原生代理执行，把坐标分高低字节编码成退出码回传），
把浏览器指针在一次移动中移到画布的不同位置，看客户机光标落在哪里（客户机屏幕 640x480）：

| 浏览器指针位置 | 期望坐标 | 修复前实测 | 修复后实测 |
| --- | --- | --- | --- |
| 画布 (0.05, 0.05) | (32, 24) | 移动 (0.04,0.06) 后落在 (42, **164**) | (30, 22) |
| 画布 (0.50, 0.50) | (320, 240) | — | (319, 239) |
| 画布 (0.90, 0.10) | (576, 48) | — | (574, 46) |
| 再次回到 (0.50, 0.50) | (320, 240) | — | (319, 239)（完全可重复，无漂移） |

修复后一次移动即精确落点，并且反复回到同一位置坐标完全一致，说明已经是绝对定位。

端到端回归：`output/post-usb-tablet-1.json` → `passed: true`、`completionRecorded: 1`、202.1 秒，
说明新增 USB 设备没有影响启动、就绪校验、客户机内检查工具与判题链路。
