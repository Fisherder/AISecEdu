# 玄甲教师登录态首页与 AI 共创改进方案

> 状态：提案，可进入产品评审与实施拆分  
> 日期：2026-08-27  
> 范围：教师登录后的首页、课程中心、全局 AI 共创、任务中心及移动端体验

## 1. 结论与产品决策

当前教师端的主要问题不是视觉风格，而是产品中心错位：教师登录后直接进入上一条 AI 对话，系统优先呈现“聊天历史”，没有优先回答“今天需要处理什么、哪些任务正在执行、哪门课程需要关注”。课程中心也主要展示静态数量，无法帮助教师决定下一步。

本方案作出以下决策：

1. 教师登录首页改为面向教学工作的 **教师工作台**，不再默认打开某条旧对话。
2. AI 成为贯穿工作台与课程的 **上下文操作层**，不再成为登录首页的全部内容。
3. 所有会改变课程事实的 AI 生成任务都采用 **理解—确认—执行—验收—审核/发布** 五阶段模型。
4. “生成 5 道题”等数量和独立性要求升级为系统级硬约束；不能只依赖提示词。
5. 任务中心成为异步 AI 工作的唯一状态来源，必须表达逐项进度、部分成功、失败和待审核状态。
6. 会话历史只保留有意义的工作记录；空会话不保存，同一任务的续跑不重复制造同名会话。
7. 移动端采用重新编排的单列工作流，关闭的侧栏必须同时退出视觉、交互和无障碍树。

## 2. 实测依据

本方案基于 2026-08-27 对真实教师登录态页面的检查，覆盖 1440 × 900 桌面视口和 390 × 844 移动视口。

### 2.1 教师 AI 首页

- `/teacher` 默认恢复上一条长对话，并停留在回答末尾，而不是显示跨课程待办或最近工作。
- 左侧出现大量同名“全流程续跑 fdae8fca”和“空对话”，工作历史已退化为运行日志。
- 会话标题没有持续显示课程、章节和操作对象，正文出现 `moduleIndex`、`solvedChallengeIds`、`verifiedCompletion` 等内部字段。
- “生成课件、生成 CTF 实践题、生成实训演示、分析学情”以产物类型组织，不符合教师“备课、出题、布置、干预”的目标心智。
- 任务抽屉只显示总进度、截断标题和“定位到对话”，缺少课程、章节、目标数量、实际数量、失败项和审核入口。

### 2.2 课程中心与课程工作台

- 课程中心卡片仅显示章节、题目、学生数量；没有待审核草稿、生成失败、学生异常、最近编辑等行动信号。
- 整张卡片与“进入课程工作台”链接执行相同动作，交互重复。
- 重命名和删除长期裸露在卡片底部，删除操作视觉权重过高。
- 课程工作台的结构和视觉层级较清晰，但“打开 AI 助手”会进入通用对话，课程上下文没有以持久、可核对的界面元素贯穿后续操作。
- “真实完成率 39%”缺少分母、统计周期、变化趋势和可采取动作。

### 2.3 批量出题问题

教师要求生成 5 个题目时，最终课程中出现的是 1 个包含五个关卡的综合题。界面没有在执行前确认“5 道独立题”，也没有在执行后检查“目标 5 / 实际 1”，因此语义偏差被错误地当作成功结果发布。

### 2.4 移动端与无障碍

- AI 首页快捷操作第三项被截断，第四项不可见，也没有明确的横向滚动提示。
- 课程卡片的“进入课程工作台”被挤成逐字竖排。
- 关闭状态的会话侧栏被移动到屏幕外，但仍保留在键盘焦点顺序中；Tab 会依次进入多个位于负坐标的不可见控件。
- 课程编辑、删除按钮约为 38 × 38 像素，触控容错不足且彼此紧邻。

以上页面没有出现影响主体内容加载的 HTTP 错误，因此核心问题属于信息架构、状态表达和响应式交互，而不是页面加载失败。

## 3. 用户目标与设计原则

### 3.1 首页必须回答的四个问题

教师进入系统后的十秒内，应能回答：

1. 现在最需要我处理什么？
2. 哪些 AI 任务仍在运行、失败或等待审核？
3. 我上次在哪门课程做到哪一步？
4. 哪些学生或课程出现值得关注的变化？

### 3.2 设计原则

- **工作优先于工具**：先呈现待办、风险和下一步，再呈现功能入口。
- **上下文始终可见**：凡是可能写入课程的操作，都持续显示课程、章节和产物类型。
- **生成前可确认，生成后可核验**：生成式 AI 不能直接跨过结构确认和结果验收。
- **部分成功不是成功**：批量任务必须保留每一项的独立状态和重试能力。
- **摘要先于证据**：教师先看到结论和动作，内部字段与完整证据按需展开。
- **离开后仍可恢复**：刷新、切换课程或关闭页面后，任务与审核状态保持一致。
- **桌面与移动端同等可完成**：移动端不以隐藏或截断关键操作换取版面整齐。

## 4. 目标信息架构

### 4.1 全局导航

教师一级导航调整为：

- **工作台**：登录默认入口，聚合跨课程待办、任务、风险和最近工作；
- **课程中心**：浏览课程并进入课程内部工作区；
- **AI 共创**：保留完整会话与深度共创能力，但不是默认登录落点。

搜索、工作区、任务通知和账户仍属于全局工具。任务通知必须带有“进行中、待审核、失败”的数量徽标，而不是只显示一个无状态图标。

### 4.2 教师工作台桌面布局

```text
┌──────────────────────────────────────────────────────────────────────┐
│ 全局导航                         搜索  任务  账户                    │
├──────────────────────────────────────────────────────────────────────┤
│ 上午好，王老师                                                   │
│ [课程：软件安全] [章节：逆向工程]  告诉 AI 你要完成什么教学工作… │
├───────────────────────────────┬──────────────────────────────────────┤
│ 需要我处理                    │ AI 任务                              │
│ · 5 道题待审核                │ · 生成逆向题 4/5 · 1 项失败          │
│ · 3 名学生需要关注            │ · 课件修订等待确认                   │
│ · 1 个课程尚未发布            │ [查看全部任务]                       │
├───────────────────────────────┴──────────────────────────────────────┤
│ 最近课程：课程状态、最近动作、明确下一步                           │
├──────────────────────────────────────────────────────────────────────┤
│ 学情变化：只显示有行动价值的异常与趋势                             │
└──────────────────────────────────────────────────────────────────────┘
```

工作台不直接展开完整会话。点击任务或最近工作后，进入对应会话/产物；点击 AI 输入栏后，在保留当前课程上下文的情况下开始新任务。

### 4.3 移动端布局

```text
┌──────────────────────────┐
│ 玄甲任务  菜单 │
├──────────────────────────┤
│ 课程 / 章节上下文         │
│ AI 指令输入               │
├──────────────────────────┤
│ 需要处理                  │
├──────────────────────────┤
│ 运行中 / 待审核任务       │
├──────────────────────────┤
│ 最近课程                  │
└──────────────────────────┘
```

快捷操作最多首屏显示两个，其余收进“更多”；禁止以被裁切的横向按钮暗示隐藏能力。课程卡主操作保持横排全宽按钮，编辑和删除收进更多菜单。

## 5. 批量出题的目标体验

### 5.1 第一步：理解教师意图

教师输入：

> 在软件安全课程的逆向工程章节，一次生成 5 道彼此独立的动态 Flag CTF 题，难度递进。

系统先形成结构化任务契约：

```json
{
  "operation": "challenge.batch.generate",
  "scope": {
    "course": "软件安全",
    "module": "逆向工程"
  },
  "requestedCount": 5,
  "independence": "independent_challenges",
  "exerciseMode": "CTF",
  "difficulty": "progressive",
  "publishMode": "draft"
}
```

`requestedCount` 和 `independence` 属于不可被模型后续改写的硬约束。生成提示词只能补充题目内容，不能把五题合并为一道五阶段题。

### 5.2 第二步：确认生成计划

在执行前显示可编辑确认卡：

```text
将在「软件安全 / 逆向工程」创建 5 道独立 CTF 题

1. 静态字符串与入口定位        简单
2. 动态调试与输入路径追踪      简单
3. 反调试识别与绕过            中等
4. 加壳程序解包与验证          中等
5. 多阶段综合逆向              困难

[调整要求]                              [确认并生成 5 道题]
```

确认按钮必须包含数量，避免用户在不知情的情况下批准被缩水的任务。

### 5.3 第三步：逐题执行

一个批次包含五个独立子任务：

- 每题独立 `taskId`、`draftId`、环境、动态 Flag、标准解和验证结果；
- 批次只负责归组、统一取消和统一修订；
- 某一题失败不得回滚或覆盖已经成功的题；
- 允许只重试失败项；
- 离开页面后继续执行，并在工作台恢复。

### 5.4 第四步：系统验收

任务终态由确定性规则计算，而不是由模型自然语言宣布：

```text
目标数量：5
已创建草稿：5
环境构建通过：5
标准解验证通过：4
需要修复：1
批次状态：部分成功，等待处理
```

只有五个独立草稿全部创建且全部满足所需验证，批次才能显示“生成完成”。实际数量小于目标数量时必须进入 `partial_success` 或 `failed`，不得显示 100%。

### 5.5 第五步：教师审核与发布

结果页以五张可独立展开的题目卡呈现，支持：

- 逐题预览、修改、重试、删除和发布；
- 全选后统一修改或发布；
- 对比原始要求与当前结果；
- 显示每题的难度、关键技能、解题机制和验证状态；
- 发布前再次确认目标课程和章节。

## 6. 任务中心

### 6.1 状态模型

任务中心统一使用以下状态：

- `planning`：正在形成结构化计划；
- `waiting_confirmation`：等待教师确认；
- `queued`：已进入队列；
- `generating`：正在生成；
- `validating`：正在构建或验证；
- `needs_review`：生成完成，等待教师审核；
- `partial_success`：部分子任务成功；
- `published`：已发布；
- `failed`：无可用结果或不可继续；
- `cancelled`：由教师取消。

### 6.2 任务卡必须显示

- 课程与章节；
- 教师原始目标摘要；
- 目标数量与已完成数量；
- 当前阶段和真实耗时；
- 失败项及可重试动作；
- 最终产物入口；
- “审核结果”作为成功后的主操作，不再以“定位到对话”代替结果入口。

### 6.3 首页曝光规则

- `waiting_confirmation`、`partial_success`、`failed` 和 `needs_review` 进入“需要我处理”；
- `queued`、`generating`、`validating` 进入“AI 任务”；
- `published` 默认折叠到历史；
- 任务数量徽标只统计需要教师注意的项目。

## 7. 会话与 AI 输出治理

### 7.1 会话生命周期

- 点击“新建对话”只创建本地临时态，发送第一条有效请求后才持久化；
- 第一轮计划形成后自动命名为“课程｜动作｜对象”，例如“软件安全｜生成 5 道逆向题”；
- 同一批次的继续、修订和发布默认回到原会话；
- 支持按课程、任务类型和状态过滤；
- 连续空会话、重复测试会话和长期无活动会话可批量归档；
- 删除或归档会话不得删除已经生成的课程事实。

### 7.2 输出层级

智能体最终答复固定采用：

1. **结果摘要**：发生了什么；
2. **验收状态**：目标与实际是否一致；
3. **下一步操作**：审核、修复或发布；
4. **依据与技术详情**：折叠展示。

禁止在默认摘要中直接暴露内部 ID、数据库字段和未经解释的英文状态名。需要排障时，通过“查看技术详情”显示。

## 8. 课程中心改进

课程卡从“库存计数”升级为“下一步决策”：

- 主信息：课程名称、角色、最近活动；
- 状态信息：待审核草稿、运行中任务、学生风险、发布状态；
- 主操作：继续上次工作或处理最高优先级事项；
- 次操作：进入课程工作台；
- 低频操作：重命名、成员和删除统一收进更多菜单；
- 课程较多时提供搜索、状态过滤、最近使用和收藏；
- 整张卡片不再与卡内主按钮形成两个相同链接。

课程工作台保留现有较清晰的“概览、课件、题目、演示、学情”，但概览首屏应优先显示待审核、异常和继续操作。完成率必须补充统计口径、时间范围和可下钻对象。

## 9. 响应式与无障碍要求

1. 关闭的侧栏使用 `inert` 并从键盘焦点顺序移除；打开后将焦点移入，关闭后归还触发按钮。
2. 弹层和抽屉使用正确的对话语义、焦点圈定和 Escape 关闭。
3. 所有主要触控目标建议不小于 44 × 44 像素；删除与编辑不得紧邻裸露。
4. 快捷操作在移动端折叠或换行，不允许无提示裁切。
5. 课程卡主 CTA 在 320–430 像素宽度保持正常横排文本。
6. 动态任务更新使用非打断式 `aria-live`；不能在用户阅读历史时强制滚动到底部。
7. 会话按钮的无障碍名称只包含标题、状态和时间，不把整段回答预览读入控件名称。
8. 支持键盘完成课程切换、任务审核、题目批量选择和发布流程。
9. 支持系统减少动效设置；进度变化不只依赖颜色。

## 10. 内容与文案规范

将能力型文案改为目标型文案：

| 当前文案 | 建议文案 | 原因 |
| --- | --- | --- |
| 生成课件 | 准备本节课 | 从产物转向教师目标 |
| 生成 CTF 实践题 | 为当前章节出题 | 明确上下文与动作 |
| 生成实训演示 | 设计课堂演示 | 区分教师演示与学生题目 |
| 分析学情 | 找出需要关注的学生 | 明确预期结果 |
| 定位到对话 | 审核生成结果 | 结果优先于过程记录 |
| 已完成 100% | 5/5 已生成，4/5 已验证 | 避免伪精确和掩盖部分失败 |

## 11. 实施优先级

### P0：正确性与可恢复性

- 建立批量出题结构化任务契约；
- 把数量、独立性和目标章节作为服务端硬约束；
- 创建独立子任务并增加批次结果验收；
- 任务中心支持部分成功、失败项重试和结果审核；
- 修复移动端屏外侧栏仍可聚焦的问题；
- 修复快捷操作裁切和课程卡 CTA 竖排。

### P1：首页与上下文

- 上线教师工作台默认首页；
- 增加“需要我处理、AI 任务、最近课程、学情变化”；
- 在 AI 输入、计划、任务和结果中持续显示课程/章节上下文；
- 空会话不落库，自动生成可识别标题；
- 课程卡增加行动信号并收纳危险操作。

### P2：效率与个性化

- 课程收藏、筛选和最近使用；
- 首页模块根据教师角色和使用频率排序；
- 批量题目难度分布、技能覆盖和重复度可视化；
- 支持保存常用出题模板，但模板不能绕过数量验收。

## 12. 验收标准

### 12.1 批量出题

1. 对中文数字、全角数字和阿拉伯数字表达的 1–5 道题，结构化计划中的数量必须完全一致。
2. 请求“5 道独立 CTF”时，生成 5 个不同的任务 ID、草稿 ID、题目入口、环境和验证记录。
3. 不允许用一个题目的五个小问、关卡或阶段满足五题要求。
4. 任一子任务失败时显示 `4/5` 和失败原因，只重试失败项不会复制其余四题。
5. 刷新、切换课程和重新登录后仍能恢复相同任务状态。
6. 教师确认前不得创建题目事实；审核发布前学生不可见。

### 12.2 首页

1. 登录后无需打开对话即可看到待处理事项、运行任务和最近课程。
2. 所有任务卡都显示课程、章节、目标数量、实际数量和下一步操作。
3. 首页不显示原始内部字段；证据可在详情中查看。
4. 没有待办时显示有价值的空状态和推荐下一步，不恢复随机旧对话。

### 12.3 移动端与无障碍

1. 在 390 × 844 和 320 × 568 视口中没有被截断的主操作或逐字竖排 CTA。
2. 侧栏关闭时，连续 Tab 不得进入任何屏外侧栏控件。
3. 任务抽屉、确认卡和题目审核可以只用键盘完成。
4. 200% 文本缩放后，数量、状态和主操作仍可见且不重叠。

## 13. 衡量指标

- 明确数量指令遵循率：1–5 道题达到 100%；
- 批量独立性通过率：目标 N 对应 N 个独立题目事实，达到 100%；
- 生成后人工发现“数量不符”的比例降为 0；
- 空会话持久化数量降为 0；
- 登录到首次有意义操作的中位时间下降；
- 任务失败后的成功恢复率提升；
- 教师从生成完成到完成审核的中位时间下降；
- 移动端主流程完成率与桌面端差距持续缩小。

## 14. 实现映射

后续实施应优先核对以下现有边界，避免另建第二套产品：

- 教师工作台模板与交互：`dojo_theme/templates/teacher_agent.html`、`dojo_theme/static/js/dojo/teaching-agent.js`、`dojo_theme/static/css/teaching-agent.css`；
- 课程中心：`dojo_theme/templates/teacher_courses.html`、`dojo_theme/static/js/dojo/teacher-courses.js`、`dojo_theme/static/css/course-hub.css`；
- 模型规划与数量约束：`services/agent-runtime/lib/server/teacher-agent.ts`；
- 持久任务和批量执行：`dojo_plugin/agent_runtime/jobs.py`、`dojo_plugin/models/global_agent.py`；
- 教师 API：`dojo_plugin/api/v1/teaching.py`；
- 真实自然语言验收：`ops/verify-natural-language-teaching-lifecycle.py`；
- 登录态 UI 与响应式验收：`ops/verify-teacher-agent-ui.py`。

实现时应复用现有全局智能体、课程事实、任务与题目模型，不增加独立“出题应用”或新的身份体系。
