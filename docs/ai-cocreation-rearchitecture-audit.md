# AI 共创重构核查（2026-09-30）

## 本次事故与边界

此前把课件上传、原文提取、模型生成章节摘要、严格结构校验放在同一条前台任务里。模型输出不稳定时，一份已经保存的文件会长期显示“分析课件”，用户无法继续依据原文工作；多份附件还会占满任务中心，并让聊天提交携带过期的 `expectedJobId` 而收到“当前任务已经变化”。这属于执行与资料生命周期耦合，不是单纯的文案或样式问题。

现在的约束是：文件存储成功即得到稳定的资料身份；原文提取是后台索引工作；模型整理是另一条可失败的后台工作。用户可立即发送消息。若请求明确依赖某份还未提取完的文件，仅该请求等待原文索引；其他聊天不等待，模型整理从不作为附件可用的前提。引用必须保留文件、修订和摘录来源，不能把整理摘要当作原文。语义整理读取已经持久化的同一版原文索引，不再重新转换原文件。

## 线上验收口径

1. 上传成功后，附件显示“已保存”；即使模型整理失败，该文件的原文索引仍可引用。
2. 同一对话连续上传多份文件时，教师能继续输入和发送；后台索引不抢占前台消息通道，也不触发过期任务冲突。
3. 任务中心只显示用户可控制的创作任务。资料索引与后台整理由系统记录和运维观测，不伪装成多个“分析课件”用户任务。
4. 请求“根据这份课件”时，必须引用该文件的原文摘录；索引未就绪只等待这项必要依赖。与附件无关的请求继续执行。
5. 失败能区分存储、提取、模型整理与生成；重试从可复用的阶段继续，不重新消耗已完成的提取。
6. Skill 仅在调用时加载所需说明；其引用资源由工具按需读取，不能把未选择的参考文档塞进每次提示词。
7. 空闲页面能按事件游标及时接收其他窗口已提交的消息；页面隐藏、切换会话与删除时停止旧等待，断线后从游标续读，不以刷新整个页面恢复。
8. 一轮对话只有一条教师可见任务；规划作业、工具驱动和后续执行不会各自冒充整轮终态。会话事件应能区分轮次与单步的执行、等待、恢复和最终结束。
