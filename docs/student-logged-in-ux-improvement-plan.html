玄甲 · logged-in student experience

把“很多页面”重构成一条可继续的学习路径

本文件是学生端 UI、交互、信息架构和关键数据语义的开发执行合同。开发 Agent 应按优先级直接修改项目，不需要重新发散产品方向；任何视觉调整都必须服务于“学生此刻知道做什么、为什么做、完成后发生什么”。

实机审查：2026-08-28 范围：登录后学生端全旅程 桌面：1440 × 1000 移动：390 × 844 依据：真实学生会话 + 当前代码 + 官方产品资料
唯一北极星判断 首页不是数据橱窗，AI 不是第二套产品，学习分析不是审计后台，工作区也不是孤立终端。它们必须共同回答：我现在应该完成哪一步，系统会如何保存和评价这次学习？
00 · Agent contract

如何使用这份文件

这不是灵感展示，也不是要求开发者“自行优化”的提示词。以下决定、状态模型、工作包和验收条件共同构成实现边界。

DO

先修正确性，再修层级

先处理错误能力、失效链接、错误状态语义与不可恢复错误，再重排导航、首页和课程路径，最后统一视觉和动效。

PRESERVE

保留可用业务与旧链接

尽量扩展现有 API；已有 canonical 路由继续可用。需要更名时只改界面术语，并提供兼容跳转，不破坏教师端和历史深链。

PROVE

每个工作包独立验收

必须有真实学生、空账号、已加入课程、已批改任务、失效资源、无权限尝试和移动视口测试；不可只做静态截图验收。

范围边界：主要修改学生端。共享导航、资源查看器、设置页和 API 权限会同时影响教师端，必须补教师回归测试；不在本轮重做教师端课程创作流程。
01 · Live evidence

真实页面给出的证据

以下结论来自当前运行项目的学生登录态，不是根据模板猜测。审查覆盖首页、课程目录、课程、章节、容器题、作业、学习分析、评分、AI 助学、个人生成空间、成果查看器、实验环境、搜索和设置。

P0 · 能力错误

学生自有成果详情同时显示“仅教师可见”和“发布”。页面以 student viewer 渲染，但 API 对资源所有者返回 canRequestPublish: true；真正提交时服务端又要求教师权限。界面承诺、API 能力与服务端授权互相矛盾。

发布按钮可见
P0 · 失效动作

AI 历史消息中的“打开无线模拟练习”指向 404。对话卡片长期保存了资源 URL，但渲染时不重新校验资源是否仍存在，也没有“已下线 / 查看替代内容”的恢复路径。

真实 404
P0 · 错误裸露

评分页直接显示“请求失败，状态码 403”。学生无法区分记录不存在、已归档、无权限或数据迁移失败；页面保留“正在读取”文案，没有提供回到有效尝试的操作。

真实 403
P1 · 空首页

零数据学生首页在移动端高达 2107px。首屏先展示四个“0”，之后是多个只有标题的空容器；AI 入口在主导航、Hero、下一步、成长区和页尾重复出现，却没有形成一次清晰的新手引导。

2107 px
P1 · 目录失控

课程目录桌面页面高达 11251px。大量测试课程以近似名称重复平铺；同一已加入课程又出现在“可加入课程”；没有搜索前置、筛选、分页、归档或环境隔离。

11251 px
P1 · 状态混写

学习分析首屏把“课程进度、S1–S4 证据可信度、结果 + 过程”并列为同级 KPI。这会让学生把完成度、能力掌握、评分结果和证据完整性误认为同一件事；“能力缺口 100%”又在没有有效证据时显得像确定结论。

4 种语义
P1 · 冗长任务

三题已批改作业在移动端高达 2755px。题目、答案、长反馈和整份总结全部串行展开；右侧桌面总结落到移动页尾，学生无法快速先看结果、再定位错题。

2755 px
P1 · 双工作区

“个人工作区”和终端图标“工作区”代表两个完全不同的对象。前者是 AI 生成的个人课件/模拟，后者是题目运行环境；AI 页、个人工作区页和成果详情又分别承担生成、管理与查看，边界模糊。

同名异义
P1 · 空实验态

/workspace 在无会话时只显示英文 “No active challenge session; start a challenge!”。移动端形成一整屏空白，没有返回课程、选择题目或最近会话入口。

无 CTA
P2 · 移动降级

页面虽然没有横向溢出，但主要策略只是纵向堆叠。AI 快捷动作被裁切，标题截断；课程/分析卡片成倍拉长；章节缺少移动端固定的上一项/下一项操作。无横向滚动不等于移动体验成立。

390 px 实测
审查补充：课程页把“0 项必修实训 / 0 / 0”的阅读章节也渲染成空进度；章节页用 Accordion 混合课程资料和实训；已批改作业默认展示参考答案；设置页仍出现“教学对话”等教师口吻；首页数据、课程会员关系与 AI 历史上下文可能不同步。
02 · Root-cause diagnosis

问题不在“卡片太多”，而在产品模型没有合拢

当前学生端像四个独立产品共享一条导航：LMS 课程、网络安全实验、证据评分系统、AI 内容生成器。每个局部都有功能，但系统没有一个稳定的“学习会话”作为主轴。

学习中心多个空区块 / 多个 AI 入口
→
课程 / 章节卡片 + Accordion
→
题目启动环境 / Flag
→
工作区脱离课程的独立工具
↘
评分 / 分析证据术语与原始状态
AI 助学对话 + 任务 + 历史动作
→
个人工作区再次输入自然语言
→
成果详情返回 AI / 发布权限混乱
→
失效深链404 / 无恢复
ROOT 01

导航按系统模块分，不按学生意图分

“学习中心 / 课程 / 个人工作区 / AI 助学 / 工作区”要求学生先理解后台对象。学生真正的意图只有继续今天的任务、浏览课程、进入实验、求助和查看进展。

ROOT 02

推荐是算法输出，不是可解释承诺

“下一步”分散在首页、课程、学习分析和 AI 中；缺少统一排序规则、预计时间、前置条件、推荐依据与替代选项，学生无法判断应该信哪一个入口。

ROOT 03

完成事实被错误地提升为能力判断

完成一道题、拿到一个分数、有完整事件链、掌握某项能力是四种不同事实。当前界面把它们压缩成进度百分比、可信度和能力缺口，造成虚假精确。

ROOT 04

资源生命周期没有进入 UI 模型

AI 消息保存静态 URL，课程和资源被关闭、清理或迁移后仍呈现为可执行按钮；查看器也不保留来源页。系统记录了对象，却没有管理对象的可用性与去向。

ROOT 05

角色通过模板猜测，能力通过所有权猜测

学生拥有个人成果时得到编辑/发布类字段，但页面又以 student viewer 隐藏部分功能；权限逻辑分散在模板、API 和动作端点，导致“看得到但做不了”。

ROOT 06

响应式只处理宽度，没有处理任务模式

移动端把桌面多列全部向下排。实验、AI 对话、长作业在手机上的任务方式本来就不同，应该一次聚焦一个面板、固定主要动作并减少历史细节。

借鉴机制，不复制皮肤

资料于 2026-08-28 核对，优先使用官方产品文档。下表只提炼与本项目直接相关的机制，并明确不应照搬的部分。

模块要求直接贴在学习项上

采用：每个课程项明确类型、完成条件、状态和锁定原因。
不采用：把所有教学对象继续做成后台式长列表。

04 · Product principles

实现时不可被牺牲的七条原则

01

一个权威下一步

所有页面使用同一排序服务。首页显示一项主要动作，课程内显示该课程的一项；AI 可以解释或替换建议，不能另造不一致的推荐。

02

先状态，再数字

先回答未开始、进行中、待批改、已完成、需补强、暂无证据；只有在定义清楚且证据充分时才显示百分比。

03

上下文不断线

课程、章节、题目、环境、评分和 AI 共享同一个 learning context；返回操作回到来源位置，而不是固定跳到 AI 或课程首页。

04

角色决定能力

界面只能渲染服务端授权的 capability。所有权不等于教师权；学生个人成果使用“仅自己可见 / 提交审核”，不能出现课程发布。

05

失效也可继续

资源不存在、环境过期、评分不可见时，使用产品化状态和恢复路径；禁止把 403、404、原始枚举或任务 ID 直接交给学生。

06

AI 是上下文能力

保留一个完整 AI 对话空间；课程与题目中以侧栏/抽屉携带上下文进入。默认辅导，生成、规划、复盘由明确的意图触发。

07

移动端一次做一件事

移动端不是缩小版桌面：课程显示当前项，作业一次聚焦一题，AI 固定输入，实验环境使用全屏标签切换或明确提示改用桌面。

05 · Target information architecture

从五个模块入口收敛为三种学生意图

保留现有路由以降低迁移风险，但重写导航命名、入口优先级和页面之间的返回关系。

有数据状态

  • 首屏只保留一个 Primary next action，显示类型、课程、预计用时、推荐原因、当前保存状态和一个主按钮。

  • 不渲染四个“0” KPI 和七个空容器。

6.2 课程目录：先分“我的”和“发现”，再展示卡片

目录规则

  • 默认 Tab 为“我的课程”；“发现课程”才显示可加入内容。同一课程不可在两个区块同时出现。
  • 发现页顶部固定搜索与筛选：主题、难度、类型（理论/CTF/模拟）、预计时长、官方/教师课程。
  • 每页最多 24 门课程，分页或可访问的“加载更多”；URL 保存筛选参数，浏览器前进后退可恢复。
  • 测试、验收、已归档内容由后端可见性隔离，不通过前端名称规则隐藏。

课程卡信息

  • 标题、教师/发布方、适合水平、预计总时长、实践类型、最新更新时间。
  • 已加入课程显示当前项与进度；未加入课程显示课程目标和“查看详情”，不在卡片上混入内部 reference ID。
  • 0 个活动的课程必须标记“仅资料 / 尚未开放实践”，不能伪装成可立即实战。

6.5 AI 学习助手与“我的创作”：一个入口，两种结果

AI 学习助手

  • 保持 /guide 为唯一完整对话空间；左栏是对话，主栏是消息，任务抽屉按需打开。
  • 从课程/章节/题目进入时显示可移除的上下文 chip：课程、当前题、可用资料、学习目标；发送前学生知道 AI 会引用什么。
  • 默认“辅导”行为：先询问卡点、给提示、分层解释和理解检查；涉及作业时遵守教师 AI 政策，不直接泄露私有答案。
  • “创建练习/课件/模拟”是明确的生成意图，结果进入“我的创作”；分析与解释不创建工作区。
  • 消息动作卡渲染前重新解析资源。资源不可用时显示“已下线”，提供回到课程或查找替代项，不保留可点击 404。

我的创作

  • /learning/extend 界面名称改为“我的创作”，删除第二套宽泛自然语言入口；主动作是“在 AI 学习助手中创建”。
  • 列表按创建目标、课程、类型和更新时间分组；相同任务生成的重复对象合并为版本，不重复展示相同卡片。
  • 可见性仅使用“仅自己可见、已提交教师、课程可见”。学生不得看到“发布课程”能力。
  • 若产品需要学生分享，新增独立的“提交教师查看”流程；不能复用教师 request-publish。

6.6 成果查看器：学习内容，不是教师流水线

学生查看已发布课程成果

只显示课程面包屑、标题、内容类型、完成/继续操作。隐藏发布检查、版本比较、生成任务、内部来源和教师私有指令。

可显示自己的版本和“继续改进”入口，但标签必须是“仅自己可见”；允许复制、重命名、删除或提交教师查看，不能发布到课程。

返回与来源

优先使用经过 allowlist 校验的 returnTo 或 history state；否则回到对应课程/我的创作。禁止所有学生成果固定返回 /guide。

8.3 资源生命周期与返回上下文

  • AI 消息保存稳定对象引用（type + id），URL 只是缓存。

10 · Responsive, accessibility and resilience

质量门槛不是“能缩到 390px”

断点与任务模式

  • ≥ 1200：课程目录/内容双栏，环境分屏。
  • 768–1199：可折叠目录，主内容优先。
  • < 768：一次一个面板，固定主要动作；避免长页右栏落到页尾。
  • 在 320、390、768、1024、1440 宽度做截图与交互测试。

WCAG 2.2 AA 基线

  • 文本对比度、4.5:1；非文本状态至少 3:1。
  • 触控目标最小 44 × 44 CSS px；不只靠颜色表示状态。
  • 完整键盘路径、可见 focus、焦点不被 sticky 区遮挡。
  • Modal/Drawer 焦点陷阱与关闭后焦点归位。

异步与失败

  • 加载超过 400ms 显示与结构一致的 skeleton；超过 8s 提供进度说明。
  • 网络重试不能重复提交作业、Flag、AI 消息或启动环境。
  • 所有保存状态使用 aria-live，但避免每次键入都播报。
  • 离线/断线后保留本地草稿并说明同步状态。
AI 移动端特例：输入框、快捷动作与系统软键盘必须共同测试。快捷动作可横向滚动时要显示截断暗示与可访问名称；更推荐折叠为“学习方式”菜单，避免当前首屏按钮被裁掉。

12 · Acceptance scenarios

必须自动化的端到端验收

  1. 新学生：登录后不显示四个 0 与空白大卡；首屏显示课程码加入、浏览课程和三步 onboarding，主导航使用目标术语。
  2. 已入课学生：首页只有一个权威下一步，包含推荐原因、预计用时和保存状态；点击进入正确课程上下文。
  3. 降级首页：overview 某个子数据源失败时，仍显示可用课程与恢复提示，不把整个首页变为空白。
  4. 课程目录：已加入课程不会同时出现在可加入列表；筛选写入 URL；超过 24 条不一次渲染；归档/测试内容按权限隐藏。
  5. AI 失效动作：被删除或下线的 resource action 显示“已不可用”和恢复 CTA，点击不进入 404。
  6. 学生个人成果：显示“仅自己可见”，无“发布”按钮；API capabilities 中 publishToCourse 为 false。
  7. 发布端点防线：学生直接 POST 教师发布端点仍被拒绝；响应不泄露课程或资源私有细节。
  8. 已发布课程成果：学生只收到 student-safe 数据，不包含教师指令、生成任务、验证详情和私有来源。
  9. 无实践章节：课程卡显示“阅读章节 · 无必修实践”，没有 0/0 进度条；若配置阅读完成条件则能正确完成。
  10. 课程路径：桌面目录持续标记当前位置；上一项/下一项保留 Tab、滚动与课程上下文。
  11. 移动章节：390px 下目录可打开，固定下一项按钮不遮内容；触控目标达到 44px。
  12. 题目到环境：从题目启动时环境继承 course/module/challenge，上屏显示启动阶段、取消/重试和剩余时间。
  13. 未知掌握度：无能力证据时显示“尚无足够证据”，不显示 0% 或缺口 100%。
  14. 待评分：提交后评估未完成时显示“等待评分”，页面不先渲染 0/100、0/60、0/40。
  15. 完整证据低分：评分低但事件链完整时，两种事实分开展示；“证据完整”不被写成学习结果可信 100%。
  16. 无权评分记录：学生访问他人/过期 attempt 时看到可理解状态和“查看我的最近尝试”，不显示状态码 403。
  17. 首页当前课程：课程会员关系与 AI 当前上下文不一致时，以授权 membership 为准，并提示切换/清除过期上下文。
  18. 作业自动保存：刷新、断网恢复和多标签页冲突不会丢失答案或覆盖较新版本；保存状态明确。
  19. 作业答案策略：未到教师允许条件时不返回/不渲染参考答案；条件满足后结果页只优先展开错题。
  20. 移动作业：390px 下默认一题一屏；题目导航可达；提交前列出未答题；结果先展示摘要再展示详情。
  21. AI 上下文：从题目进入显示课程和题目 chips；移除 chip 后服务端不再使用对应上下文；默认先给提示而非私有答案。
  22. 搜索：键盘可打开、输入、上下选择和关闭；结果按对象分组且只包含用户可见内容；空结果提供下一步。
  23. 历史深链：/learning、/guide、旧课程/章节/题目和成果 URL 继续可达或正确 308，query/fragment 不丢失。
  24. 我的创作去重：同一生成任务的版本合并显示；继续操作回到对应对话/成果，不产生重复卡片。
  25. 实验环境空态：无 active session 时显示中文说明、返回当前课程/浏览实践入口和最近会话，不出现英文孤立句。
  26. 实验环境移动端：一次只显示题目、终端、桌面或连接信息；不发生三栏压缩、嵌套横滚或软键盘遮挡。
  27. 启动失败：环境准备失败提供阶段化原因、幂等重试和返回题目；重复点击不会创建多个 session。
  28. AI 移动输入：390px 下消息列表、快捷方式和 composer 均可操作；标题不影响返回/任务按钮，安全区适配软键盘。
  29. 键盘与焦点：导航、Tab、Modal、Drawer、课程目录、问题导航和查看器完整可用；关闭后焦点返回触发器。
  30. 动态播报：autosave、环境启动、AI 任务和错误使用合适 live region，不重复刷屏。
  31. 视觉状态：完成、当前、锁定、失败、未知不只靠颜色；深色主题达到 WCAG 2.2 AA 对比度。
  32. 教师回归：教师成果编辑、验证、发布、学生安全预览与课程中心不因共享查看器/导航修改而退化。
13 · Delivery order and definition of done

建议四阶段交付，不做一次性大爆炸

PHASE 0

正确性

SP00–SP02：fixture、权限、资源生命周期、错误和状态语义。

PHASE 1

主路径

SP03–SP05：首页、导航、目录、课程学习壳与题目路径。

PHASE 2

深任务

SP06–SP08：作业、AI/创作、成果查看器与实验环境。

PHASE 3

硬化发布

SP09–SP10：移动、无障碍、性能、埋点、灰度与回滚。

Definition of Done

  • P0 问题全部有 API 与浏览器回归测试。
  • 32 个验收场景通过，关键页面有桌面/移动截图。
  • 无学生可见原始 403/404、SOLVED、ACTIVE、S1–S4 或内部任务 ID。
  • 新学生、有效学生和降级数据三种首页均成立。
  • 学生资源能力与服务端授权一致，教师发布回归通过。
  • 320–1440px 无意外横向滚动、遮挡或不可达动作。
  • 键盘、焦点、live region、对比度与 reduced motion 检查通过。
  • 关键指标、错误恢复和 feature flag 可观测、可回滚。

开发 Agent 最终交付内容

  • 按 SP 编号列出改动文件与决策，说明兼容处理。
  • 给出 API schema 变更和迁移/弃用窗口。
  • 附测试命令、通过结果、未运行项与原因。
  • 附 1440 × 1000、390 × 844 的关键前后截图。
  • 列出剩余风险，不能用“后续优化”代替 P0 未完成项。
完成判定 当一个学生从登录开始，能在十秒内判断下一步；在课程、题目、环境、AI 和反馈之间移动时不丢上下文；在没有数据、没有权限或资源失效时仍然知道如何继续——本次重构才算完成。
