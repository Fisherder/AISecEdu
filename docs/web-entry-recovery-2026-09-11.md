# 10.92.35.7 网页入口修复

2026-09-11，范围为 AISecEdu 网页访问和入口跳转。

## 原因与证据

SSH 和网页使用不同端口，SSH 可用并不代表网页入口的协议配置正确。本次复现发现：

- `https://10.92.35.7:8443/healthcheck` 返回 200，应用、数据库和模型运行时健康。
- `http://10.92.35.7:8443/...` 返回 400、`Connection: close`，响应明确说明普通 HTTP 请求发到了 HTTPS 端口。这与截图连接终止的现象相符。
- `http://10.92.35.7:8080/...` 跳转到 `https://10.92.35.7/...`，遗漏实际 HTTPS 端口 8443；宿主 443 端口属于另一个已有服务。
- 原课程为私有课程。已有成员登录后可访问截图中的完整 URL，未登录返回 404 不代表课程已删除。

## 修复

- 8443 和 Workspace 4443 收到普通 HTTP 请求时返回 308，升级到同一地址的 HTTPS，保留端口、路径和查询参数。
- 8080 使用平台配置的 `AISECEDU_PUBLIC_ORIGIN` 跳转，准确保留 8443。
- 公开入口配置通过 Compose 环境与 Nginx 模板生成，显式挂载模板，容器重建后持续有效。
- 在 `ops/verify-local.sh` 增加端口、路径、查询参数和 Workspace 入口的实际跳转检查。

## 验收

| 检查 | 结果 |
| --- | --- |
| HTTP 8443 → HTTPS 8443 | 308，保留路径与查询，跟随后 200 |
| HTTP 8080 → HTTPS 8443 | 307，保留路径与查询，跟随后 200 |
| HTTP 4443 → HTTPS 4443 | 308，跟随后 200 |
| 证书验证 | 使用部署 CA 验证通过，无需关闭服务端证书检查 |
| 应用和模型运行时健康 | 均为 200 |
| 浏览器访问原课程链接 | 已有验收账号登录后 200；无脚本错误或请求失败 |
| 运行服务保留 | 仅重建 Nginx，其余 19 个 AISecEdu 容器 ID 未变化 |

没有修改课程内容、课程成员或题目环境，没有新建账号。配置备份在服务器 `/srv/aisecedu-dojo/cache/web-entry-fix-20260911/`。
