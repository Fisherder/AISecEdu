# 全站加载性能诊断与优化记录

日期：2026-08-28  
范围：匿名首页、认证入口、学生首页、教师工作台、课程中心、平台管理、共享请求层。

## 结论

慢并非单一后端问题，而是六类成本叠加：旧版全局脚本无条件加载、首屏请求串行且重复、隐藏页签提前计算、大集合没有分页、只读页面清空缓存后逐项查询，以及重型 AI 出题只有一个消费者导致队首阻塞。修复后，真实 Chromium 的公共、学习、教学与后台核心样本全部通过预算；服务端页面/API/静态资源共 25 个目标全部通过预算。

## 根因与处理

1. **旧运行时进入所有页面。** 公共首页和旧后台会下载并解析与当前任务无关的 CTFd vendor、图表和管理脚本。新版公共/认证页显式关闭旧运行时；`/admin` 与 `/admin/statistics` 改为无图表、无额外 API 的服务端教育运营概览。
2. **课程详情首屏过度计算。** 旧请求同时计算隐藏的课件、题目、演示集合与深度学情。workspace 默认只返回当前可见骨架，集合按页签加载，学情只在进入学情页签时计算。
3. **教师页启动串行和重复。** 教师上下文、线程、任务、核心工作台改为并发；导航直接消费任务中心事件，不再竞争性请求第二份 bootstrap。
4. **轮询频率固定。** dashboard/job 轮询改为自适应退避，页面隐藏时降频，恢复可见时再同步，且禁止同一轮询重叠。
5. **网络失败缺乏统一边界。** `RequestClient` 统一提供超时、取消、GET 去重、只读重试、`Retry-After`、短期缓存、最新响应保护和写操作缓存失效；写操作只有具备幂等键时才允许显式重试。
6. **异步数据造成“页面慢”的感知。** 教师工作台四个数据区从首帧保留稳定尺寸并展示语义化加载状态；结果在区域内滚动，学情异步返回不再把整页向下推移。
7. **KaTeX 与非关键提醒占用关键路径。** 仅在正文检测到公式后于 load/idle 阶段加载 KaTeX；成就检查和导航任务摘要延后并限频。
8. **管理集合随数据线性膨胀。** 用户、题目、课程与提交记录统一改为服务端过滤、排序；高密度用户、题目和提交记录默认每页 25 条。聚合统计只针对当前页 ID 查询，完整提交内容只在管理员主动复制时读取，不再写入列表 HTML。
9. **配置读取主动制造缓存未命中。** 配置 GET 不再清空全局缓存，也不再对每个 key 调用一次 `get_config`；改为一次读取并按原有规则转换。普通设置分区使用约 2 KB 的轻量保存器，Vue、CodeMirror、时区库与旧管理运行时仅在主题、自定义字段、备份、参与模式和运行时间分区按需加载。
10. **重型 AI 任务出现队首阻塞。** 课堂交互与原生出题已经分流，但单个作者消费者仍会让后续独立题目或人工发布检查等待十几分钟。作者流改为两个有界消费者；每题仍保持独立持久任务、五轮质量上限、租约、取消与恢复语义，不通过降低质量换速度，也不会向模型服务制造无界并发。
11. **课程切换触发整页导航与重复渲染。** 课程卡片改为 history API 驱动的工作区切换；旧请求会通过 `AbortController` 取消并由序列号拦截过期响应，详情只渲染一次。加载期间保留稳定骨架，失败时在原位提供重试，不再出现列表闪回、点击后长时间静止或快速切课时旧数据覆盖新数据。
12. **异步状态没有闭环。** 学生 AI 工作台曾在初始请求后保留 `aria-busy=true`，视觉和辅助技术都会误判为仍在加载；现在请求开始、完成、失败及过期响应都有成对状态收束。教师输入区同时补齐可访问名称，性能验收把“可交互”而非“HTML 已返回”作为完成条件。
13. **核心工作台读取了不参与展示的大型历史字段。** 教师工作台轮询只显示课程、任务与待处理项的摘要，却曾随查询一并读取并反序列化草稿的完整对话与候选包、已完成任务结果、线程上下文及助手消息正文。相关查询现在使用 SQLAlchemy 字段投影，仅加载卡片实际消费的列；发布状态仍直接读取数据库，没有增加可能造成状态滞后的结果缓存。

## 复现

```bash
DOJO_LISTEN_ADDRESS=192.168.3.111 \
  ./ops/verify-system-performance.py --samples 5 \
  --output output/system-performance.json

./ops/verify-browser-performance.py \
  --output output/browser-performance.json
```

浏览器报告的默认路由会先在无 Cookie 状态测量 `/`，再注入管理员会话测量 `/student`、`/teacher`、首门教师课程与 `/admin`，避免把首页重定向误记成公共页面。

管理大集合与配置拆包可以单独复测：

```bash
./ops/verify-browser-performance.py --route /admin/users \
  --route /admin/challenges --route /admin/submissions \
  --route /admin/config --output output/admin-browser-performance.json
```

报告额外记录实际表格行数、页面高度、横向溢出与无名称交互控件；这可以阻止后续改动把“大数据全渲染”或不可访问控件重新带回首屏。

## 设计依据

- [web.dev：通过 code splitting 减少 JavaScript 载荷](https://web.dev/articles/reduce-javascript-payloads-with-code-splitting) 与 [JavaScript 启动优化](https://web.dev/articles/optimizing-content-efficiency-javascript-startup-optimization) 建议降低非当前任务脚本的下载、编译与主线程成本。
- [web.dev：优化长任务](https://web.dev/articles/optimize-long-tasks) 建议拆分阻塞主线程的工作，并将非关键任务移出首屏路径。
- [MDN `AbortSignal`](https://developer.mozilla.org/en-US/docs/Web/API/AbortSignal) 为可取消请求和过期响应保护提供浏览器标准机制。
- [Moodle：Caching Moodle at Scale](https://docs.moodle.org/dev/images_dev/2/29/Caching_Moodle_at_Scale.pdf) 强调按层缓存，并避免让昂贵计算进入每次页面请求。

当前已知边界：AI 模型生成和容器启动属于长任务，不承诺在普通页面时限内同步完成；产品采用“立即确认、后台持久任务、可离开、可恢复、失败可重试”的交互契约。

统一验收中的两个真实模型生命周期套件需要显式传入 `--allow-external-model-suites`。该开关代表操作者已授权把隔离生成的合成测试课程与作答发送给当前配置的外部模型；默认不发送，其他页面、浏览器、API、性能和本地生命周期套件不受影响。
