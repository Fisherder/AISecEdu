# 玄甲统一智能体架构

## 产品边界

玄甲只提供一套智能体工作台与会话交互模型。教师从 `/teacher` 进入，学生从 `/guide` 进入；两者共享同一套侧栏、对话、任务抽屉、结果卡片、输入器、线程管理与响应式布局，但由服务端分别绑定教师能力和学生能力。统一的是产品体验与状态模型，不是权限：学生端只读取本人课程、题目、尝试、证据和记忆，绝不获得课程写操作、教师私有答案或其他学生数据。

教师的原始自然语言请求直接进入模型驱动的规划—工具—观察循环，智能体可以分析资料、管理课程、生成或修改内容、创建以 Flag 验收的 CTF 题、组织课堂、分析学情并交付可下载文件。课程或章节是可选工具参数，不是对话入口，也不是模型理解请求前的强制分类。学生请求进入同一视觉工作台下的学生安全适配层，用于规划学习、解释、复盘、创建个人练习和继续课程任务。

课程中心负责浏览和管理既有事实；创建与修改动作可以从课程页发起，但必须回到同一个全局对话。系统不提供第二个生成产品、独立智能体、独立账号或独立课程工作流。

## 运行结构

```text
统一工作台
  -> 教师 /teacher -> /pwncollege_api/v1/teaching/*
     -> 模型自主规划与技能选择
     -> 受权限约束的玄甲工具
     -> PostgreSQL / Redis durable jobs
     -> agent-runtime（不可独立使用的渲染与互动执行能力）
     -> 产物卡片、课堂、CTF 或可下载文件
  -> 学生 /guide -> /pwncollege_api/v1/learning/guide*
     -> 本人课程、题目、attempt、证据与记忆
     -> 学生安全工具与个人工作区
     -> 持久对话、学习任务与结果卡片
```

`services/agent-runtime` 是全局智能体的内部能力运行时。它复用 vendored OpenMAIC MIT 源码中的渲染、Stage、场景和媒体组件，但没有产品身份。它不能独立登录、列出课程、创建权威课程数据或作为站点入口运行；非集成模式除健康检查外一律返回 404。

技能只安装在仓库根目录 `agent_skills/`，并以只读方式挂载给全局智能体。规划阶段只看技能名称与描述，执行阶段按本轮自然语言目标动态载入最多六个完整技能；不存在 OpenMAIC 专属技能目录或第二套技能选择器。当前技能覆盖文件交付、材料分析、教案/课件、CTF、模拟实训、学情、Notebook、浏览器自动化、安全审查、课程设计与评测质量。

教学产物不是一次性文本模板：课件默认生成 12–15 个实质页面（教师明确页数优先），每页都保存独立讲稿并在预览中随当前页同步；CTF 必须以隔离环境中的动态 Flag 为完成标准并通过私有解法与重置验证；模拟实训使用状态机、数值/布尔控制、同步证据通道、事件历史和确定性重置。对已有模拟的自然语言修改会重新生成真实交互 HTML，同时保留产物标识和版本链，不能只修改标题或摘要。

## 唯一事实来源

- 用户、角色、课程、章节、题目、发布状态、成绩和学习证据：玄甲 PostgreSQL。
- 对话、动作、审批、任务、材料、候选、产物、版本、课堂与文件：玄甲 PostgreSQL；Redis 只负责可恢复执行。
- CTF 完成：提交 Flag 后由确定性检查器判定。
- 运行时缓存：只用于渲染和互动执行，不得成为课程或成绩事实。

旧表 `openmaic_launch_tickets` 在启动时先做受限 JSONL 快照再移除；新表为 `global_agent_launch_tickets`。旧 `/openmaic/*` 只重定向到 `/teacher`，不会暴露应用。

## 身份与安全边界

浏览器保持玄甲身份。嵌入式预览只获得短期、一次启动、范围受限的 `aisecedu_agent_runtime` 能力 Cookie；Nginx 不把平台长期 Cookie 转发给运行时。能力每次使用都会回查当前用户、课程成员关系和工具权限，因此它不是第二套用户身份。

教师请求不会被前端关键词规则改写成固定任务类型。模型先理解原始请求，再自主选择技能与工具；只有真正改变外部事实的高风险动作需要确认。工具结果必须作为下一轮模型观察返回，模型不得把“计划执行”说成“已经完成”。

登录与注册使用同一课程系统入口。学生可在注册事务中选择公开课程或凭邀请标识和邀请码入课；教师注册只表达开始方式，不直接授予教师权限，创建第一门课程后才获得该课程的管理关系。账号创建、课程成员关系和自定义字段要么一起提交，要么一起回滚。

## 内容契约

- 请求文件时，智能体返回带鉴权下载地址的真实文件；支持 DOCX、Markdown、文本、JSON、CSV、HTML 和 Notebook。
- 实践题一律使用动态或受保护的 Flag 验收，不要求学生把结论写入 JSON。
- 一次请求生成多道彼此独立的题目时，必须为每题创建独立草稿、独立环境、独立动态 Flag 和独立持久任务；批次标识只用于归组，单题可分别查看、修订、发布、取消和删除，兄弟任务的失败不得覆盖已成功结果。
- 需要状态机交互的实践题使用 `HYBRID`：学生先完成可回放的场景目标，再从隔离运行环境取得并提交动态 Flag；`SIMULATION` 只表示教师演示或不参与 CTF 判题的互动内容。
- 演示就是演示，不伪装成题目或评测任务。
- 运行时内部交互结构使用 `experience` 与 `aisecedu.global-agent.artifact.v1`，不向模型或教师暴露供应方产品 schema。

## 代码与部署边界

- `dojo_plugin/agent_runtime`：内部任务、文件、范围、验证和运行时适配。
- `dojo_plugin/models/global_agent.py`：全局智能体的持久事实。
- `services/agent-runtime`：无独立产品入口的渲染/课堂执行进程。
- `/agent-runtime/*`：仅供受限 iframe、课堂和内部 API 使用；根路径跳回 `/teacher`。
- `/pwncollege_api/v1/teaching/runtime/*`：服务间能力网关，不是教师工作流。

上游包名 `@openmaic/*` 与 MIT 许可证归属必须保留，这是供应链与版权事实，不构成产品名称或运行边界。

## 验收门禁

1. `/teacher` 能处理分析、写操作、课堂、CTF 和文件请求，而不是统一归类为课件；`/guide` 使用同一工作台结构且只能访问学生自己的学习范围。
2. `/openmaic` 不再提供页面、API、会话或监控入口。
3. `agent-runtime` 在未启用玄甲集成时除健康检查外返回 404。
4. 跨教师、跨学生、跨课程和扩大 scope 均被拒绝；一次性票据不可重放。
5. 真实模型请求能返回文件并下载，工具执行结果会被模型复核。
6. Python、JavaScript、TypeScript、定向单测、生产构建、浏览器 E2E、监控和部署健康检查全部通过。
7. 运行过程、最终答复、结果、文件、审批与失败恢复使用不同的语义容器；刷新页面后状态一致，任务运行期间不会误重复发送。
8. 专注、标准、详细三种会话视图可切换；移动端、键盘、实时状态、减少动效和历史阅读位置均可用。
9. 注册可原子完成学生入课；教师注册不自授高权限；受保护课程在所有入课入口都校验邀请码。
10. 请求五道独立题时展示五个独立任务和五个题目管理入口，任一题失败、取消或重试不改变其他题的终态。
