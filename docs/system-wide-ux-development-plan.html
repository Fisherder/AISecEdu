System-wide UX / Product / Frontend / Backend contract

把多套页面，收敛成一个可信的教学系统

本文件是可直接交给开发智能体执行的系统级改造规格。目标不是“统一换皮”，而是修复页面、路由、权限、状态和数据之间的断裂，让公共访客、学生、教师、课程管理员和平台管理员始终知道：我在哪、现在是什么状态、下一步是什么、失败后如何继续。

范围：公共端 + 学生端 + 教师端 + 课程管理 + 系统管理 证据：70 个桌面/移动角色页面 + 关键交互 + 源码/API 优先级：P0 正确性 → P1 结构 → P2 效率 → P3 优化 交付：代码、迁移、自动化、截图、指标与回滚

Execution protocol

开发 Agent 必须遵守的执行协议

先把事实和恢复路径修对，再调整层级与视觉。不得以静态稿、CSS 换色或“看起来更简洁”作为完成。

MUST · 01

以服务端事实为准

角色、能力、资源生命周期、运行环境、批次数量和发布状态必须由服务端契约提供。前端不得通过 URL、所有权、是否出现某字段来猜权限或状态。

MUST · 02

兼容现有资产和深链

保留已发布课程、作业、成果、历史链接与当前验证脚本。变更路由时添加解析器或显式 301/302/410；不得用永久 404 掩盖未迁移对象。

MUST · 03

每包可独立验收与回滚

每个工作包都要包含迁移、feature flag、单测/E2E、失败恢复和截图证据。避免横跨全站的一次性模板重写。

MUST · 04

保留任务差异

学生端可沉浸、教师端可高密度、管理端可表格化；统一的是壳层、语义、状态、键盘行为和错误契约，不是把所有页面做成同一种卡片。

MUST · 05

先覆盖全状态再接真实数据

组件至少覆盖 initial/loading/ready/empty/degraded/error/stale/forbidden。创建 fixture 时包含零数据、部分成功、失效资源、无权限、长内容和并发冲突。

DO NOT

禁止表面交付

不得新增另一套孤立导航、重复状态枚举、页面内 fetch 封装或 CSS token；不得把原始异常、数据库 ID、任务 ID、枚举名直接显示给最终用户。

范围保护：现有 student-logged-in-ux-improvement-plan.html 与 teacher-logged-in-ux-improvement-plan.html 是子域详细规格。本方案吸收其结论，并增加公共端、系统管理、跨角色能力、通用资源/错误契约和迁移顺序；实现时若细节冲突，以本文件中的系统级契约为准，以子方案中的页面细节补充。

Root diagnosis

深层问题是五种“系统真相”没有合拢

页面长、卡片多、风格不一只是表象。根因是导航真相、对象真相、状态真相、权限真相和操作真相分别由不同页面临时解释。

01 · NAVIGATION

入口按历史模块堆积

“今天、学习、导学、课程、工作区、AI、Self Learning、教师 Agent、课程管理、CTFd Admin”并存。用户为了完成一个意图穿过多个壳层，返回动作常跳到固定页而非来源上下文。

02 · RESOURCE

同一教学对象被多套表表达

Dojos/Modules/Challenges、学习草稿、教学成果、资料、作业、自学工作区都有自己的 URL、状态和序列化；搜索、目录和查看器无法复用同一解析规则。

03 · STATE

进行中、可用、完成、发布混为一谈

容器是否运行不等于学习是否可继续；交过作业不等于掌握；AI 任务完成不等于内容可发布；有一个生成结果不等于“五题生成成功”。

04 · CAPABILITY

角色和所有权替代能力契约

注册时的“教师意图”、是否拥有课程、是否为 admin 被页面各自推断。多能力用户在学生/教师/平台管理之间缺少显式模式切换，普通学生甚至可直接打开 Git 导入页。

05 · ACTION

每页都在争夺“主操作”

教师首页的对话、任务、提醒和历史同时抢首屏；课程概览把所有指标和快捷操作一次展开；管理页把同步、导出和删除放在同一层级。没有“此刻唯一下一步”。

06 · DELIVERY

前端巨型脚本固化耦合

teaching-agent.js 超过 7,000 行，teacher-courses.js 约 3,900 行，teaching.py 超过 12,000 行；页面 fetch/unwrap/status mapping 重复，使小改动难测试、难回滚。

核心判断：先建立“一个资源解析器 + 一个能力上下文 + 一套页面/异步状态 + 一套错误恢复 + 按角色配置的壳层”，再做页面减法。否则删掉一批卡片后，矛盾会以另一种形式返回。

Benchmark mechanisms

借成熟机制，不复制成熟产品的皮肤

选择官方产品文档和设计规范作为机制证据。每项只提取能解决本项目具体问题的行为，并明确不照搬之处。

参考成熟机制玄甲采用明确不复制
Canvas Student To Do跨课程日程、截止日期与状态在一个行动列表中。“今天”只呈现一个权威下一步 + 有日期/原因的短待办。不复制完整 LMS 日历，也不把没有时限的挑战伪装成截止任务。
Moodle Dashboard / My courses个人行动面与课程浏览面职责分开。学生“今天”负责继续行动，“课程”负责我的/发现/归档。不复制可任意堆块的仪表盘，避免失去产品优先级。
Google Classroom feedback / Learning Goals提交、反馈、学习目标之间的关系清晰。作业结果把“提交事实、教师反馈、目标掌握、证据”分开。不复制 Classroom 的课程流首页；玄甲仍以实验/挑战路径为主。
Open edX build/publish / unit workflow / role preview草稿、预览、发布、学生可见性和角色预览是显式流程。教师内容统一经过 draft → validate → review → preview → publish。不把简单章节创建做成重型 Studio 步骤器。
GitHub Codespaces lifecycle创建、运行、停止、重建、删除是不同环境状态。工作区区分学习尝试、runtime、snapshot、恢复动作和过期原因。不暴露基础设施术语、容器 ID 或配额实现。
GitHub Copilot agent sessions长任务可离开、可追踪、可恢复，状态与产物分开。教师批量生成用 batch 摘要 + 5 个独立 item + 逐项重试。不把开发代理的 PR/分支隐喻直接移植给教师。
Carbon Data Table / Pagination高密度表格有批量操作、筛选、分页、空/加载状态。系统管理表格采用服务端分页、列优先级和选择后操作。不把学生课程/挑战卡强行表格化。
GOV.UK task list / error summary多步任务状态清楚；错误摘要把用户带到具体字段。长表单采用分区任务状态、顶部错误摘要和字段错误锚点。不复制政府服务视觉语气。
WCAG 2.2 / WAI Dialog / Combobox / Tabs键盘、焦点、名称、状态和目标尺寸有可验证规则。共享组件实现一次并自动审计，页面不再手写行为。不以“ARIA 属性存在”代替真实键盘和读屏测试。

Non-negotiable principles

实现时不可被牺牲的八条原则

代码审查与产品验收都应逐条检查。若局部设计与这些原则冲突，局部设计必须调整。

01

一个上下文，一个主操作

每页只突出一个主要动作；危险操作与低频工具退居更多菜单或 Danger Zone。

02

能力决定可见性

服务端返回 capability，壳层按能力渲染。多能力用户显式切换“学习 / 教学 / 平台管理”。

03

状态必须说真话

异步、资源、发布、学习、评测、环境分别建模；任何成功文案都必须对应可验证完成条件。

04

失败也有下一步

403/404/410/409/422/5xx 都要翻译为可理解状态、保留上下文并给出恢复动作与 request ID。

05

来源与返回不丢失

深链、侧栏和成果查看器携带安全的 returnTo/context；返回恢复筛选、页码、标签和滚动位置。

06

移动端按任务重排

不是缩小桌面：一次完成一项、主操作粘底、列表和详情分步、环境/内容用清晰模式切换。

07

AI 产出先审后发

自然语言是输入方式，不是绕过结构和验证的捷径；批次数量、独立性、质量门槛由服务端硬约束。

08

渐进替换，不双轨漂移

新增共享契约后迁移旧页面并删除旧实现；禁止长期保留两套导航、状态映射或 API envelope。

Target information architecture

按用户意图组织，而不是按历史模块组织

公共端完成认知与选择；学生端完成学习；教师端完成教学编排；平台端完成治理。模式切换负责跨身份，不把所有入口塞进同一导航。

System issue register

按根因登记，而不是按截图修补

以下问题均需落到代码、接口和验收。ID 在工作包和验收矩阵中复用，开发 Agent 不得只处理其中的视觉症状。

UX-01
P0
路由生成与路由能力不一致

模拟/混合练习、feed、管理菜单、成绩页。

根因：每个页面自行拼接 href；目标路由再依据另一套对象条件判断。

实现：新增服务端 ResourceResolver，所有 API 输出 canonical href + availability + reason；模板禁用字符串拼路由。
验收：全站内部可见链接无意外 4xx/5xx。

UX-02
P0
数量型 AI 指令被当作软提示

“生成 5 题”曾只得到一个结果。

根因：自然语言解析、任务数量、产物数量与 UI 成功态没有同一批次约束。

实现：requestedCount 进入持久 batch contract，建立 5 个独立 item job；聚合状态不吞并逐项事实。
验收：现有五题生命周期脚本 + 部分失败/幂等重试。

UX-03
P0
学习状态与 runtime 状态冲突

“可继续实验”与“没有运行环境”同时成立。

根因：attempt/snapshot/container/session 被压成一个布尔值。

实现：返回 learningAttempt、runtime、snapshot 与 recommendedAction；文案按组合映射。
验收：运行中、停止可重建、已过期、启动中、失败五种路径一致。

UX-04
P0
权限靠页面猜测

注册意图、课程所有权、平台管理员相互混用。

根因：没有全局 capability context；模板按 user/admin/owner 分支。

实现：认证 bootstrap 返回 modes/capabilities/scopes；所有写操作仍在服务端校验。
验收：直接 URL、隐藏按钮、API 调用三层权限结果一致。

UX-05
P1
导航和身份模式不可预测

教师、学习、CTFd 管理三套壳来回切换。

根因：全局导航按模板来源定义，不按能力模式定义。

实现：统一 AppShell 接口和显式模式切换；各模式保留自己的一级 IA。
验收：刷新/深链后仍显示正确模式和 aria-current。

UX-06
P1
同一对象多套身份和状态

草稿、成果、资料、课程内容在搜索/列表/查看器中不一致。

根因：缺少跨表 presenter/envelope。

实现：不急于合并数据库表，先建立 canonical ResourceSummary 和状态映射层。
验收：同一对象在列表、详情、搜索、任务中心标题/状态/href 一致。

UX-07
P1
首页职责膨胀

教师工作台、课程概览、管理首页都把所有模块首屏展开。

根因：把“有数据可展示”误当“用户此刻需要”。

实现：首屏固定：异常/待处理 → 一项主行动 → 关键摘要；解释和历史渐进展开。
验收：首个决策不需要跨过超过两个同权模块。

UX-08
P1
错误是技术响应，不是产品状态

JSON parse、裸 404、空白区、内部枚举。

根因：接口 envelope 和前端请求层不统一；页面各自 catch。

实现：统一 error contract、RequestClient、AsyncBoundary 和角色相关 recovery action。
验收：故障注入下没有未处理 Promise、原始 HTML/堆栈或死按钮。

UX-09
P1
搜索不是可信导航

匿名不可用，教师仍得到学生目标，模拟题命中死链。

根因：单一搜索接口未理解模式、capability、资源生命周期。

实现：按模式分组索引并通过 resolver 返回动作；匿名只搜公开目录。
验收：每种模式结果范围、权限、空状态和键盘行为通过测试。

UX-10
P1
管理端仍是竞赛后台

指标、语言、密度与教育运营不匹配。

根因：直接暴露通用 CTFd 管理 IA 和数据表。

实现：新增平台运营 shell/presenter，逐步包裹底层 CTFd 能力；保留高级兼容入口。
验收：管理员能在 3 次点击内定位失败任务、异常 runtime、权限和课程问题。

UX-11
P2
移动端只做宽度压缩

首屏动作过多、表格缩小、上下文栏挤压。

根因：没有 task mode 和组件级响应策略。

实现：学生底部主导航、列表/详情分步、管理表格行摘要、粘底操作和安全区。
验收：360/390/768px 真机尺寸无横向溢出，关键任务单手可达。

UX-12
P2
设计 token 和组件所有权分散

--product/--ui/--theme/--cs/--agent 并行。

根因：按页面追加 CSS，缺少 primitive → semantic → component 层。

实现：建立 token 映射和共享组件；主题只覆盖 semantic token。
验收：新页面无需复制按钮/状态/抽屉样式，主题切换无语义错色。

UX-13
P2
巨型脚本降低迭代可靠性

教师脚本和 API 文件过大。

根因：状态、网络、DOM、工作流、格式化和 telemetry 混在一起。

实现：按 feature/service/state/component 拆分，建立公开模块边界和 contract tests。
验收：主页面只做组合；业务流可无 DOM 单测；无循环依赖。

UX-14
P2
可访问性无法系统复用

缺 skip link、重复 ID、复杂控件名称不足。

根因：dialog/tab/combobox/table 由各页面手写。

实现：共享可访问组件 + axe + 键盘 E2E + 读屏抽查。
验收：WCAG 2.2 AA 基线，关键流无 serious/critical 自动违规。

UX-15
P2
无法判断改造是否改善任务

缺少旅程级指标和统一错误事件。

根因：埋点按点击，不按用户意图和状态转移。

实现：定义 journey ID、resource context、state transition 和隐私最小化事件。
验收：可度量首次有效行动、批次达成、恢复成功和不可恢复错误率。

UX-16
P0
辅助路由绕开安全产品边界

加入密码可进入 URL；教学 metrics 无显式访问保护；Discord 失败返回裸 JSON/501。

根因：历史/API/集成路由没有纳入页面、错误和 capability 审计。

实现：加入码改 POST；metrics 用独立运维认证/网络策略；集成回调进入统一恢复页。
验收：浏览器历史/日志无加入秘密，metrics 非授权不可读，集成失败可恢复。

Page-by-page specification

逐页开发规格：目标、层级、逻辑与边界

8.5 跨角色能力：只实现一套事实，按模式呈现

GLOBAL SEARCH

模式感知命令面板

公开端只搜公开课程；学生搜课程/章节/题目/作业/成果；教师搜教学对象/批次/材料；管理员搜治理对象。结果返回 capability-filtered action，而非前端拼接 URL。

NOTIFICATIONS & JOBS

通知不等于任务

通知是已发生的信息；任务是需要用户行动；后台 job 是系统过程。壳层只显示需处理数和运行数，分别进入过滤后的列表。

ERROR & RECOVERY

统一恢复面板

错误携带 code、message、recovery、retryability、requestId；页面保存上下文与草稿。重试必须幂等或提示影响。

THEMES

主题是偏好，不是产品分裂

学生可使用沉浸主题，教师/管理保持高可读工作主题；所有主题覆盖相同 semantic token、对比度和组件状态。

RETURN CONTEXT

安全返回协议

returnTo 必须是站内已授权路径；同时保存 tab/filter/page/scroll。无有效来源时回到当前模式的对象集合，不写死首页。

PAGE METADATA

每页都是可识别的产品页面

设置唯一 <title>、H1、canonical 路径、主内容 ID、aria-current、request context；浏览器标题格式为“页面 · 上下文 · 玄甲”。

Canonical contracts

先统一页面所依据的事实，再统一组件

数据库表可以渐进迁移，但 API 边界必须先提供稳定的资源、能力、状态、链接和错误语义。以下契约是所有新页面和迁移页面的共同入口。

Natural-language batch authoring

“生成五题”必须成为可证明的系统事实

数量不是提示词修辞。解析结果、持久批次、独立任务、聚合状态、审核 UI 和自动化验收共同保证数量与质量。

1. 解析指令课程、章节、5、主题、难度、材料
→
2. 计划确认5 个独立草稿 · 不自动发布
→
3. 建立 BatchrequestedCount=5 · idempotency key
→
4. 生成 5 Items每题独立 job / draft / validation
→
5. 审核与发布逐题修复/重试 · 学生预览 · 批量发布
STEP 1 · PARSE

结构化意图，不直接执行聊天文本

  • 解析输出 objectType=ctf_challenge、requestedCount=5、course/module、五个 topic/difficulty 计划、source material 与 constraints。
  • 数量、课程、对象类型为硬字段；缺失才追问。教师可在确认卡直接修正。
  • 防止 prompt 中的例子/引用被误解析为额外指令；记录 parser version。
STEP 2 · CONFIRM

确认的是执行计划，不是空泛“好的”

  • 显示“将创建 5 个独立题目草稿”，列出每题主题/难度；说明验证、预计时间、发布策略。
  • 主动作“开始生成 5 题”；次要“调整计划”。禁止按钮只写“生成”。
  • 确认请求带 idempotency key，双击/刷新不得建立两批。
STEP 3 · PERSIST

先建 5 个 item，再调度

  • 事务内创建 batch + 5 item records，item index 唯一；成功后入队，不让并发回调决定题目数。
  • batch 保存 requested/created/validated/published/failed/canceled 计数，但计数从 items 投影。
  • 同一 idempotency key + user + scope 返回原 batch。
STEP 4 · EXECUTE

逐题隔离、验证与恢复

  • 每个 item 有独立 job、draft、topic、difficulty、attempt、errorCode；失败不取消已成功项。
  • 生成后进入结构校验、题解/flag/运行验证和安全检查；验证失败为 needs_review/failed，不计 validated。
  • 批量并发受课程/模型/运行资源限流；重试只针对选中 item。
STEP 5 · PRESENT

聚合摘要永远不吞掉逐项事实

  • 顶部始终显示“已请求 5 · 已创建 N · 已验证 N · 失败 N · 已发布 N”。
  • 只有 created=5 才能写“5 题已生成”；3/5 显示“部分完成”，并提供“重试 2 项”。
  • 逐项卡显示状态、最后更新、问题、重试/编辑/预览；列表更新支持轮询退避或事件流降级。
STEP 6 · REVIEW

发布是教师行为

  • 默认不自动发布；教师可单题修改，也可对全部已验证项执行批量学生预览。
  • 批量发布只包含勾选且 validated 的项；未通过项不得被静默忽略，确认中明确列出。
  • 修订指令“把这 5 题都调难”建立 batch revision，并保持五个 item 对应关系。

13.1 WCAG 2.2 AA 与 WAI-ARIA 实施门槛

STRUCTURE

结构与名称

  • 每页唯一 title/H1/main，首个可聚焦元素为 skip link。
  • 地标、标题层级、列表/表格语义真实；图标按钮有可访问名称。
  • 状态不能只靠颜色；时间/计数包含文本含义。
KEYBOARD

键盘与焦点

  • Dialog/Drawer trap + restore；关闭区域 inert。
  • Tabs 使用 roving tabindex；Combobox 支持方向键/Enter/Esc。
  • 排序、分页、批量选择、拖拽都有键盘等价动作。
FORMS

表单与错误

  • 可见 label、说明和错误正确关联；错误摘要链接到字段。
  • required/格式/范围不只用 placeholder 表达。
  • 自动保存和冲突用 live region，且不反复打断读屏。
VISUAL

视觉与缩放

  • 文字/控件对比达到 AA；focus indicator 不被遮挡。
  • 200% 缩放可完成关键任务；正文可放大到 400% reflow。
  • 目标尺寸至少满足 WCAG 2.2 24px 最低要求，产品目标 44px。
MOTION / MEDIA

动效与内容

  • prefers-reduced-motion 下取消非必要移动/闪烁。
  • 进度动画有文本状态；图表有数据表或摘要。
  • 终端/模拟器提供可读状态与非颜色提示。
TESTING

自动 + 人工

  • axe 只作基线；每个核心流必须全键盘运行。
  • NVDA/VoiceOver 至少抽查登录、作业、AI、批次、管理表格。
  • 中文长文、英文 ID、长课程名、空值和错误组合测试。

16.1 数据与路由迁移规则

  1. 先加后切：新增 presenter 字段、batch/item 约束、capability 和 canonical href；旧 consumer 暂可忽略新字段。
  2. 双读不双写：迁移期 adapter 可从旧模型读取并映射；写操作只进入一个权威 service，避免批次/状态分叉。
  3. 校验回填：为历史资源计算 availability/workflow/source/version；无法映射的进入 data-quality 队列，不默认 published。
  4. 按 surface 灰度：先内部管理员/测试课程，再教师，再学生，最后匿名公共；不得随机把同一用户的关联页面分到不同契约。
  5. 记录兼容调用：旧 endpoint/route 响应带 deprecation header 并记录匿名计数；使用归零一个发布周期后删除。
  6. 回滚保持新数据：旧 UI 至少能只读显示新批次/成果，或提供安全 adapter；回滚不得删除新 item、草稿或提交。

16.2 关键风险与决策

管理端是否完全替换 CTFd新增教育运营壳，CTFd 高级页暂保兼容入口。所有底层操作已有新 presenter/审计/验收。逐项迁移并度量旧入口使用。

DEFINITION OF DONE

系统级完成定义

  • 所有 P0 问题有复现测试并修复。
  • 所有可见路由通过全站 crawler，无意外 4xx/5xx。
  • 四模式 IA、capability 和 mode switch 在深链/刷新下正确。
  • 资源、状态、错误、分页和页面 bootstrap schema 有 contract tests。
  • “五题”生成 exactly 5 items，并覆盖部分失败/单项重试/幂等/刷新/修订。
  • 学生、教师、管理员关键旅程不泄露越权数据。
  • 360/390/768/1024/1440 视口关键流通过。
  • 键盘、焦点、读屏抽查和 axe 门禁通过。
  • 性能预算、故障注入和长任务恢复通过。
  • 事件不包含禁止字段；监控可发现数量不符和状态矛盾。
  • 迁移/回滚演练成功，无草稿、批次、提交或成果丢失。
  • 旧实现有明确删除清单，不留下永久 adapter。
