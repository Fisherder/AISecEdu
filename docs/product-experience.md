# 玄甲产品体验架构

## 产品焦点

玄甲只呈现四个稳定的教学领域：

1. **课程**：课程、章节、成员与发布范围；
2. **内容**：原始资料、AI 课件、教案与版本；
3. **实训**：CTF 容器题、互动仿真与课堂演示，以及对应的 Flag 判题和过程证据；
4. **学情**：由判题、尝试、过程证据和评估形成的学习状态。

AI 是贯穿上述领域的交互方式，不是与它们并列的第五套业务。教师可在任何课程上下文中发起 AI 共创，生成结果仍回到课程、内容或实训的唯一事实来源。

社区、排行榜、独立课堂、独立作业和独立设置不再占用一级导航或课程工作区。已有底层路由与历史数据只保留兼容能力，避免破坏现有课程；新的用户路径统一回到课程、实训与学情。

## 角色入口

### 教师

- **课程中心**：按课程查看课件、CTF、互动演示与学情；
- **AI 共创**：跨课程自然语言操作、持续对话、任务与产物记录。

实训和学情是课程内部工作区，不再重复出现在全局导航。

### 学生

- **学习中心**：下一项任务、课程进度与正在进行的实验；
- **课程**：可加入和已加入课程；
- **AI 练习室**：课件解释、互动仿真与知识测评；
- **AI 助学**：与教师 AI 共创共用一套工作台和线程交互，基于学生自己的课程、题目和学习证据持续对话。

工作区、搜索、账户和主题切换属于全局工具，不占用业务主导航。

## 教师课程中心

课程中心只保留四个一级视图：

- **概览**：课程健康度、章节结构和明确的下一步；
- **课件**：上传资料、AI 生成课件和版本详情；
- **实训**：分别管理以 Flag 验收的 CTF 实践题和无判题的课堂演示；创建与修改统一交给全局智能体；
- **学情**：学生完成、尝试、评分、证据可信度与最近活动。

成员、权限和底层 Studio 作为低频课程管理工具收纳在概览末端，不再与日常教学任务并列。

概览只突出当前最重要的教学下一步；课程设置与运行记录默认折叠。学习分析只保留“下一步、能力、学习记录”三个视图，完整实训目录回到课程页面查看。

## 交互原则

- 页面先回答“现在最重要的下一步是什么”，再展示完整数据；
- 全局智能体不固定绑定某一课程或章节；每次操作从自然语言与对话记忆确定目标，生成、发布和评估仍写入经过权限校验的明确课程事实；
- 课程、章节和题目的稳定标识由系统自动生成并处理冲突，教师界面只呈现名称、内容与教学属性；
- 教师只面对一个全局智能体；生成、渲染、课堂、实训、文件和数据分析都是它的工具能力，不呈现第二个智能体或第二套产品；
- 学生和教师使用同一套智能体信息架构、任务抽屉与结果表达；服务端按角色隔离数据与工具，视觉统一不得被实现成权限合并；
- 一次生成多道独立题时，一题对应一个持久任务和一个题目管理入口；批次只做归组，不把多题包装成不可拆分的单个结果；
- CTF 实践题统一以 Flag 验收；课堂演示不伪装为题目，也不要求学生提交 JSON 报告；
- 自动评分必须区分确定性结果与 AI 过程评估；
- 所有一级入口保持角色一致、命名一致、位置一致；
- 高风险写操作继续确认，安全只读操作直接完成；
- 桌面和移动端均保留清晰的焦点、键盘导航与减少动效支持。
- 桌面正文不低于 17px，主要控件不低于 15px，说明与元数据不低于 13px；移动端正文保持 16px 基线，只有图标和装饰编号可例外。
- 全站颜色必须读取课程主题语义令牌，并遵循 [课程主题系统](course-theme-system.md)；不得在业务组件内新增与具体主题绑定的颜色分支。

## 全局智能体会话信息架构

全局智能体的会话不是普通聊天记录。界面按事实状态呈现六类信息：

1. **教师要求**：右侧独立显示原始自然语言，允许复制和再次编辑；
2. **实时执行**：使用独立执行卡显示当前步骤、公开事件、停止入口和任务详情，不把“正在理解”之类占位语伪装成助手答复；
3. **最终答复**：使用明确的“智能体答复”容器呈现结论、证据和必要说明，支持标题、列表、引用与代码；
4. **任务结果**：课程操作、内容草稿、CTF、演示和分析结果统一放在“结果”区，完成后不保留第二套完成进度；
5. **交付文件**：文件名、格式、大小和鉴权下载入口放在独立“交付文件”区，请求文件时必须出现真实下载链接；
6. **确认与恢复**：高影响操作进入“下一步操作”，失败或取消进入可重试恢复卡，不能用成功语气掩盖终态。

会话提供三种密度，并跨会话保留教师选择：

- **专注**：请求、最终答复、结果、文件和必要确认；
- **标准**：默认视图，在专注内容之外保留折叠的执行记录；
- **详细**：展开计划、所选技能和公开任务事件，适合检查智能体行为。

任务运行时，输入区允许教师准备下一条要求，但发送按钮保持禁用并提供显式停止入口，避免重复提交。页面刷新后从持久消息元数据和任务事件恢复相同状态；轮询更新不会强制把正在阅读历史的教师拉回底部，新内容改用“回到最新”提示。

这些约定参考成熟编码智能体的结果—过程分层：OpenAI 的模型指南把工具输出与最终 assistant message 视为不同输出，并要求最终答复以结论、证据和下一步为主；Claude Code 的官方桌面文档提供 Normal、Verbose、Summary 三类呈现密度，`/focus` 只保留工具摘要、编辑统计与最终答复。实现仍遵循玄甲自身的教师任务、安全审批和课程事实边界。
