# 实践题通用规范 v1.1.0

- 明确实践环境、入口、预期操作对象、恢复方式、开始状态与完成条件。
- 实践目录应有可辨识的任务身份；可变学生数据与平台只读工具分开。不同任务不能共用同一份学生代码或结果。
- 公开检查用于反馈，正式核验由受控检测器给出；学生可以修改自己的文件，但不能通过修改公开测试替代正式成绩。
- 保留必要运行记录及版本，错误反馈可操作。环境失败、编译失败和答案不通过应分开说明。
- 只声称已经实际执行的验证。复用已有题时保留其真实完成协议，不凭空添加报告或额外提交步骤。

## 统一作业目录

每道编码或文件型实践题只有一个学生工作区。课程路径用稳定的小写英文 slug，作业用 `hwNN-topic` 或 `labNN-topic`；中文名称用于界面和说明，不作为路径。编号在课程内各自的 hw、lab 序列保持唯一，不因改标题而改路径。Linux 为 `/home/hacker/courses/<course>/<assignment>`，Windows 为 `C:\Courses\<course>\<assignment>`。纯状态模拟题仍遵守自己的状态契约，不强制创建虚假的文件工程。

小型编码题将主源文件直接放在根目录，保持现有 coding 规则。多文件或逆向实践可按职责增加 `work/`、`materials/`、`tests/`、`results/`，没有用途的目录不要生成。`work` 放学生实际修改的对象；`materials` 放题目输入与参考文件；`tests` 仅放公开测试；`results` 放实际生成的反馈。安装包、环境维护、历史工具、其他题目、教师答案和正式隐藏测试不进入学生工作区。不能靠文件隐藏属性代替职责分离或访问控制。

根目录至少有说明、一个检查入口与机器可读的清单。说明须指出编辑哪个文件、在哪个目录执行检查、正式提交什么、哪些材料不参与判定、如何恢复；不要求额外报告。入口名称、网页说明、桌面快捷方式、编辑器打开路径和检查器实际读取路径必须一致。Linux 编码保留 `make check`、`make submit`；Windows 旧题可使用 `check.cmd` 调用原检测器并沿用平台完成协议，不能假造并未实现的独立自测。

`workspaceLayout` v1 必须包含 `course`、`assignment`、`studentRoot`、`editablePaths`、`materialPaths`、`graderRoot`、`checkEntry`、`submitEntry`、`testVersion` 和 `reportRequired:false`。文件列表使用安全相对路径，正式检测器在工作区外。coding 已有 `coding_workspace` 与 `codingGrading` 的工程可推导这份清单；显式清单必须与实际编码工程一致。课程和作业编号重复、文件未部署、检测入口不能运行仍需运行时验收，静态校验不会冒充环境验收。

迁移必须只初始化不存在的学生文件，保留已编辑文件及原有检测器。旧系统无法提供链接时可一次复制迁移，但必须规定唯一的新编辑路径；显式检查前同步到旧检测器读取路径，备份被替换的旧文件，并在文件被占用时停止而不是误报通过。每次启动重新核对入口和必要文件，不因存在历史回执就跳过检查。未知学生文件不能被清空。

## 核验与发布验收

公开自测负责反馈，正式检测器执行受控核验；仅有公开测试通过不能算正式成绩。新检测器输出至少包含作业标识、检测版本、提交对象摘要、开始结束时间和逐项结果，并区分环境失败、编译失败、超时与测试失败。学生可见反馈与服务器保存的正式证据分开；本地结果文件不作为可信成绩。已有动态 Flag 题保留服务器绑定账号与题目的判定，不把它降级为报告题。

发布前在新环境和已有学生磁盘各验一次：启动后工作区正确、编辑后检查读取同一对象、停止再启动保留改动、另存后仍能检查、重复迁移不覆盖工作、检查失败不产生新的通过凭证。变更只影响目录时仍要核对原件和检测器 SHA-256；这只能证明文件未改，不能代替实际正式检测。

## 研究依据

- [CS50 Hello](https://cs50.harvard.edu/x/psets/1/me/)：明确进入题目目录、编辑指定文件，检查与提交指令分别给出。借鉴路径和操作对象明确一致，不复制其账号体系。
- [CS61A Homework 1](https://site.cs61a.org/hw/hw01/) 与 [Lab 0](https://site.cs61a.org/lab/lab00/)：编号题包包含源文件、Ok 工具与配置，可按问题检查；本地得分检查与正式提交区分。玄甲保留自己的测试工具。
- [Gradescope Autograder Specifications](https://gradescope-autograders.readthedocs.io/en/latest/specs/)：提交、检测程序和结果各有独立位置，逐项结果定义可见范围。玄甲借鉴职责和证据分离，不照搬其运行路径。
